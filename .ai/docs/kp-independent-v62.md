# KP 独立认证 v62

用户明确 KP 登录与普通 Web 准入是不同认证方式，KP 用户不应因未加入公网 IP 白名单被 `public_ip_denied` 拦截。本次替代历史 KP 共用 IP/设备准入的要求，不修改现场网络映射。

## 实现

- 公网入口仅把注册的 KP 建立/心跳/关闭、一次性票据兑换、会话状态及 `/kp/` 静态资源交给 KPHandler 独立处理。普通首页、账号密码登录及匿名业务请求继续原 IP/设备准入。
- 后续业务访问只有通过 identity 的有效 KP 关联 Bearer 校验，才能独立于 IP 白名单准入。校验保留账号状态、版本、会话期限、KP 租约与撤销；持续读取同样复核。普通密码 Bearer、Cookie、伪造令牌不享有此准入。
- KP 无需额外申请设备证书；若连接提交了证书，保留既有 TLS 及设备绑定检查。公开路由范围、站点权限、受限维护权限及物理写限制保持。
- KP 外站 iframe 使用已发放、绑定 peer/host 的供应商能力地址取得内部会话校验，不向供应商发送 HMI 凭据；能力不能访问通用 API。关闭关联会话后旧能力失效。
- KP 配置页和 Web 白名单说明同步；不迁移配置或用户工程，不自动扩大普通 IP 白名单。Windows/Web 完整覆盖包版本为 v62，未部署现场或18153，不含新版安卓 APK。

## 验证

专项已通过：无 IP 白名单/无客户端证书的正式 KP 登录、Origin/CORS、一次性票据、数据读取、伪造和普通 Bearer 拒绝、路径规范/公开路由限制、桥接撤销及持续读取失效；联调固定账号/站点范围、轮换/停用保持；外站 native/trial × IP/device/KP 三种准入组合验证凭据隔离、peer 绑定和关闭失效。

新增真实 main 装配的隔离 HTTPS 测试：证书信任链验证、空白名单、正常本机 API 建号/登录/配置 KP，再经现有 WAF 执行无效令牌拒绝、有效令牌核验/兑换/业务读取、普通 Web 拒绝、写入拒绝和 KP 关闭撤销。KP 核验上游为隔离 HTTP fixture，不是现场 KP 实际登录验收。
