# 5000变量与50人并发性能分析

日期：2026-10-27。范围为当前发布包代码审查、隔离压测及单浏览器观察；本轮没有实施性能改造。

## 已明确的使用条件与结论

用户要求总库5000变量、MQTT每秒一次、50人同时使用；随后补充KingIO按首次全量、后续变化发布理解，每个运行画面最多50–100变量，只有开发页面可能查看全部。现场KingIO实际发布配置、心跳与重连补全行为尚未抓包确认。

后续按用户要求咨询“解答疑问”会话并核对旧项目文件，找到真实KingIO测试源的变化增量证据，详见文末追加；首次全量在旧客户端中由连接后主动查询实现，不能直接假设订阅本身触发全量。

**该使用规模有合理的优化空间，但当前发布版本不能直接认定满足50人实时使用。** 已实测实时通道32连接硬上限；运行端仍接收权限范围内全量数据，未按当前画面订阅。5000值每秒全变化是本轮压力边界，不是对现场日常变化率的估计。

如果50个页面各订阅100变量，即使所有订阅值每秒变化，也约为5000次“变量×客户端”更新/秒；当前人人接收5000值、每秒两次是500000次/秒。两者相差100倍的是变量条目发送次数，实际字节数还取决于协议、时间戳、质量、元数据和重连频率，不能直接宣称网络或CPU降低100倍。

CPU整机按16逻辑处理器归一化；32连接无存储阶段约占1.04个CPU核。RSS为约每秒采样的最大工作集，不是系统捕获的绝对峰值。网络统计为SSE data行字节，不含TCP/TLS等开销。

- 采集短测 **passed**：190个批次、950000个样本全部进入并处理，最终队列清空，接收/运行队列均无丢弃，无解码错误。不能据此承诺长期5000/s性能。
- 50实时连接 **failed**：32个HTTP 200，18个HTTP 503；这是全服务连接限额，不是用户账号数量限额，多标签页也会占用连接。
- 当前全量推送每帧约1349047字节，每0.5秒一帧。若仅放开连接数，按单连接线性推算50人约1.08 Gbps应用层负载，此数为推算，未实测50个成功连接。
- 全库每秒历史存储 **failed**：两阶段均出现 `context deadline exceeded`，已提交samples记录均为0。事务失败回滚；结束时表及索引占约26.7 MB不能用作成功记录的每行空间估算。存储拖慢实时快照，32连接帧间隔P95约2.234秒。
- 每秒保存全部5000值对应每天4.32亿条记录。用户尚未要求该存储周期，此项仅作压力边界；变化存储、按点分级周期和保留时长需要业务定义。

## 单浏览器观察

独立Chrome打开开发态变量监视，在MQTT持续更新下显示5000/5000正常；初始可访问性树呈现56个变量按钮，搜索04999可定位最后一个变量且值和时间继续更新。说明列表虚拟化与筛选可用，不代表全部5000卡片同时绘制。

前台20秒观察：requestAnimationFrame回调1063次、间隔P95 16.9ms、最大133.3ms；37个超过50ms的主线程长任务，最长136ms；JS heap约95.6MB。此为浏览器调度观察，不是Flutter实际绘制帧率或50客户端渲染验收。存在短暂卡顿，不能宣称完全流畅。页面保留可见的历史存储错误，关闭存储不会伪装为先前写入成功。

## 代码原因及拟改进方向（尚未实施）

1. [runtime_stream.go](../../backend/internal/server/runtime_stream.go) 的全局容量32、500ms推送全量；身份模式调用 `SnapshotJSONFor`，未使用匿名兼容路径的250ms共享缓存。应在负载降低后调整有界连接容量，覆盖50独立会话与多标签页。
2. [runtime/access.go](../../backend/internal/runtime/access.go) 先复制全部运行状态，再按站点权限过滤。应通过公开订阅契约限定当前画面的稳定变量ID，和既有授权取交集；跨站绑定也逐项授权。不能把前端提交的变量集合当成权限。
3. SSE采用首次全量、后续增量：初始返回订阅值与版本，后续仅变化值/质量/必要时间状态；名称、单位等配置按配置版本同步。取消订阅、切图、权限变更、配置删除、断线/陈旧变化也要传播。携带连接代次或序号，重连/缺帧时重新全量，避免增量漏值；只推变化不等于直接转发原始MQTT报文，因为还有缩放、虚拟点、权限和状态变化。
4. [engine.go](../../backend/internal/runtime/engine.go) 接收时仅更新本批中的源点位，其余最新值保留，所以已能合并上游增量。但 `snapshotLocked` 与 `usable` 依源时间判陈旧；纯变化发布下正常恒定值可能超过StaleMS而变陈旧，虚拟点也会受影响。需先明确KingIO心跳、质量和周期刷新约定，再区分最后值变化时间、最后确认有效时间与来源状态；不能仅凭broker连接在线就认定PLC数据永远有效。
5. [runtime/policies.go](../../backend/internal/runtime/policies.go) 持有引擎锁调用2秒超时存储；[storage/store.go](../../backend/internal/storage/store.go) 在事务内逐条 `ExecContext`。拟采用批量写入与锁外有界存储队列，保留错误、排队/提交区别及背压指标；不得仅延长超时掩盖阻塞。
6. [main.dart](../../app/lib/main.dart) 每次全量快照重建运行集合与工作台状态；[variable_matrix.dart](../../app/lib/features/variable_matrix.dart) 已有惰性网格。拟由前端按稳定ID合并增量，并仅更新受影响的可见组件；开发端全量监视单独分页/按可见范围处理。

建议下一轮验证使用首次5000全量、后续每秒50/100/500变化以及5000全变化边界；50个独立授权会话各订阅50–100变量，加入恒定值、断线、重连、权限撤销、切图和存储故障。具体变化率与历史策略还需以真实配置/抓包为据。
