# 物料管理 · AI 开发需求

版本：V0.3，2026-11-13。状态：用户已授权实施，尚未验收。

本次最终决定优先于下文V0.2历史待定项：支持部分库存转类；同一物料按分类分余额，退库选择已有分类；档案单价选填，出库采用当时档案价及金额快照，缺价显示已知小计和缺价行数；审批通过、出库及退库必须本人签名。数量/单价4位、金额2位；具体默认值和实施测试见[实施与验收](material-management-implementation.md)。本轮已获开发和隔离验证授权，未获现场部署授权。

本文件承接[初版需求](material-management-requirements-v1.md)，新增“采购申请至入库”“出库及退库”两条流程追溯。用于 AI 开发、测试及交接，不是报价清单。整体产品要求仍由[agent.md](../../agent.md)维护，工程边界遵循[架构契约](architecture.md)。本次仅编写需求，不代表授权开始开发或部署。

## 1. 范围与术语

- 新增物料管理模块：申请与审批、品类管理、入库管理、库存管理、出库管理五个页面。
- 扩展既有个人账号页面的签名功能、用户／角色页面的业务权限。
- 单仓库；Windows、Web、KP、安卓及手机浏览器共用同一套业务数据。
- 本文“采购申请单／申购单”对应此前的文字需求申请。用户此次称“采购单”，在当前范围中按采购申请单处理；不另建供应商采购订单系统。
- 采购办理在线下：不增加供应商、询价、采购合同、付款或财务核算。
- 申请仍只填一段文字；不因增加追溯而强制改成结构化物料申请表。
- 入库可独立办理，也可关联已通过的申请并分批入库。
- 出库直接办理，不以申购单或审批为前提。退库由原出库人办理，允许分批退回。
- “废品”是分类。此前的“作废”已明确为转移品类，不是删除、报废扣账或单据作废。

## 2. 页面和功能

| 模块／页面 | 必须实现的功能 |
| --- | --- |
| 物料管理／申请与审批 | 文字申请、本人记录、待审批列表、通过／驳回、驳回修改重提、审批签名、历史版本；从申请详情追溯关联入库 |
| 物料管理／品类管理 | 最多10层分类；维护物料名称、规格、单位、单价、预警值；支持快速建档及“废品”分类 |
| 物料管理／入库管理 | 选择物料、独立或关联申请入库、分批入库、整单多图凭证、入库记录；从入库详情追溯原申请和审批 |
| 物料管理／库存管理 | 物料库存、低库存提示、品类转移；从物料查看库存流水及对应业务单据 |
| 物料管理／出库管理 | 直接出库、用途、签名、出库记录、Excel出库单、原出库人分批退库；从出库详情追溯扣账及退库 |
| 账号管理／个人账号 | 上传、更换个人签名图片，历史签名不随更换变化 |
| 权限管理／用户及角色 | 五项业务权限分别配置、组合授权；服务端执行相同授权规则 |

流程追溯在原单据详情、记录列表和库存流水内提供，不另增业务审批，也不默认新建第六个业务页面。详情可以是页内展开、抽屉或详情视图，适配各端。

## 3. 权限与身份

| 权限 | 操作及范围 |
| --- | --- |
| 申请及查看 | 提交文字申请、查看本人申请、修改本人被驳回的申请并重提 |
| 查看及审批 | 查看全部申请、通过或驳回；禁止审批本人申请 |
| 入库 | 选择已有物料、办理入库、上传整单凭证、查看入库记录 |
| 出库 | 办理出库、查看出库记录、导出单据；只可退回本人原出库单的物料 |
| 品类管理 | 维护分类和物料档案、设置预警值、转移品类 |

- 五项权限可组合；申请查看与申请权限绑定，审批查看与审批权限绑定，不再细拆开关。
- 入库快速新建分类／物料同时需要品类管理权限；仅有入库权限时选择已有物料。
- 签名只由本人维护，审批和出库使用当前真实操作人的签名，不能选择他人的签名代签。
- Actor、操作人ID、服务端时间、权限及可退数量由后端确定，不接受客户端冒填身份或直接设定余额。
- 原出库人已失去出库权限时不得继续退库；本期不增加管理员代退或代理签名流程。
- 所有端沿用现有认证及准入边界；库存写入必须通过命名业务权限开放，不能为了新模块将远程接口整体改成可写。

### 3.1 追溯权限实现要求

- 追溯是现有业务权限下的查询能力，不增设第六项“追溯权限”。
- 用户查看本人申请时，可查看该申请的关联入库摘要：单号、时间、物料及数量、办理状态。不得顺带获得全仓库记录。
- 入库人员选择申请时，只查询可用于入库的已通过申请，展示用于核对的必要内容；不因此授予审批权限。
- 直接打开原单详情、凭证、签名图片或导出文件时，按目标资源重新鉴权；不能因为能看到一个关联ID就自动读取全部敏感附件。
- 所有列表、计数、详情、图片和导出接口采用一致的数据范围。无权展开时显示“无查看权限”，不泄露正文或附件地址。
- 上述关联摘要投影是追溯所需的技术设计。实施前核对现有权限模型，不能把摘要查询实现为无范围的跨权限读取。

## 4. 基础业务规则

### 4.1 申请和审批

1. 一段文字提交采购需求，生成唯一申请ID和可展示单号。
2. 单级审批，一名审批人通过即完成；必须与申请人不同。
3. 通过时保存审批人、时间及签名快照；驳回必须填写原因。
4. 驳回后由原申请人修改并重提，沿用同一申请ID，增加修订版本。
5. 保留每次提交的正文和对应审批决定，不能用新正文替换旧审批依据。
6. 已通过的申请不能直接改正文后继续沿用原批准；批准后重开／撤回不在当前需求内。

### 4.2 品类和物料

- 分类数量不预设业务上限，层级最多10层；后端防止循环、越层和无效父分类。
- 分类下面建立具体物料。库存、单位、预警值属于具体物料，不在父子分类上重复记账。
- 同一稳定物料ID贯穿单据和流水；不同规格或单位分别记账，不自动换算单位。
- 数量支持小数，单价允许记录；采用精确十进制或等价的定点表示，不能用二进制浮点累计库存。
- 库存小于或等于预警值时标红并提供文字提示；低库存不冒充零库存或禁止有库存的正常出库。

### 4.3 入库和凭证

- 一张入库单支持多条物料明细；确认入库后才增加库存。
- 可不关联申请。关联时只能选择已通过的申请，保存批准版本。
- 同一申请可产生多张入库单，不把后一次入库覆盖为前一次。
- 每张入库单可上传多张纸质清单照片，允许不传；照片归属整张单据，不要求逐物料上传。
- 手机支持拍照和相册选图；上传失败保留表单和已成功上传的图片，可重试或明确移除失败项。
- 用户已选择但上传失败的图片，不能在确认时无提示丢弃。明确移除后才按无附件或少附件入库。
- 保存草稿、图片上传完成与正式入库成功是不同状态。

### 4.4 出库和退库

- 有出库权限即可直接办理；用途默认“日常维修领用”，可选择其他用途或自行填写。
- 出库确认时扣减库存，保存当前出库人签名；不足库存拒绝，不产生负库存。
- 退库关联原出库单及原明细，由原出库人操作，不能只填物料名形成无法追溯的独立退库。
- 支持多次部分退库。每条明细的累计退库量不超过原出库量，退库成功后增加库存。
- 退库记录使用办理当时的本人签名，不改写原出库单签名。
- 正式出库后自动生成单据数据，可导出含签名图片的Excel文件。
- 出库成功但导出失败时，库存仍按已出库显示。只能重试导出，不得为了重出文件再次扣库存。

### 4.5 品类转移和历史

- 物料可转入“废品”或其他品类，记录前后分类、操作人、时间。
- 转类不改变仓库物料总数量，不删除原入库、出库或退库记录。
- 单据保存当时的物料名称、规格、单位、分类及签名快照；当前档案更名或转类不改写历史快照。
- 整项转类与部分库存转类的粒度尚未确定，见第11节。不得擅自加入报废损耗、核销、单据作废等业务。

## 5. 新增追溯一：采购申请单至入库

### 5.1 追溯链

采购申请单 → 每次提交版本 → 审批通过／驳回 → 通过版本 → 一次或多次关联入库 → 入库明细、纸质凭证及库存增加流水。

线下采购不建立虚假的“已采购”节点，不据审批通过推断采购完成，不据有入库记录推断全部到货。

### 5.2 正向查询

从申请详情查看：

1. 申请单号、申请人、各次申请内容和提交时间。
2. 每轮审批人、决定、理由、时间；有权限时显示当时签名。
3. 已通过的具体申请版本。
4. 该申请关联的全部正式入库单，按批次列出单号、入库人、确认时间。
5. 每批物料名称、规格、单位、入库数量及已记录单价。
6. 按稳定物料ID和单位汇总已入库数量，不能将“米”“个”等混加成一个数量。
7. 有权限时查看每张入库单的纸质凭证、原单详情和库存流水。

### 5.3 反向查询

从入库详情可返回其来源申请，查看对应批准版本及审批记录。独立入库明确显示“独立入库／未关联申请”，不伪造来源申请。

本版技术基线：一张入库单至多关联一张申请，一张申请可关联多张入库单；合并多申请入一张单未获确认，不隐式实现。一个批次可包含多种实际入库物料。

### 5.4 状态表达

| 状态维度 | 展示与依据 |
| --- | --- |
| 审批 | 待审批、已驳回、已通过，由当前提交版本及审批决定确定 |
| 入库关联进度 | 无正式关联入库时“尚无入库记录”；已有正式关联入库时“已关联入库”，显示批次数及明细数量 |
| 单笔入库 | 草稿与已入库分开；只有正式确认成功才计入库存及追溯汇总 |

申请为纯文字，缺少可计算的计划数量，因此本期不自动显示“全部到货”“完成率100%”或计算未到货数量。如后续要求采购闭环完结，需要另行确认手动完结还是增加结构化计划数量。

### 5.5 关联不可漂移

- 入库引用稳定申请ID及批准版本，不能按文字、姓名或单号模糊匹配。
- 入库确认时再次检查申请存在且该版本已批准。
- 正式入库后不能直接替换来源申请。纠错机制尚未授权时不得通过修改外键静默改变历史。
- 追溯查询从已保存的关联记录生成，不能依赖前端拼接或当前列表的加载范围。

## 6. 新增追溯二：出库及退库

### 6.1 追溯链

出库单 → 正式出库确认 → 物料扣减流水及出库人签名 → Excel单据 → 零次、一次或多次退库 → 退库增加流水及退库人签名。

Excel下载是单据输出，不是新的库存业务节点；重新导出不得创建新的出库事实。

### 6.2 出库详情必须能看到

1. 出库单号、出库人、确认时间、用途、原始明细及当时签名。
2. 每条物料原出库量、累计已退量和剩余可退量。
3. 每次退库的单号、时间、操作人、退回明细、数量及对应签名。
4. 对应的出库扣减流水、退库增加流水，可回到原业务单据。
5. 原出库单Excel导出入口，历史单据内容不随当前物料或签名变化。

### 6.3 状态与数量

- 正式出库单按各行退库量显示“未退库”“部分退库”“全部退库”。
- 每行剩余可退量 = 原出库量 − 该行全部正式退库量。
- 只要仍有明细未全部退完，整单不能显示“全部退库”。
- 单据状态按逐行条件判断，不通过不同计量单位数量相加判断。
- 并发退库、重复点击、网络重试均不能突破剩余可退量。
- 导出失败、下载取消或用户未保存文件，不改变出库／退库状态。

### 6.4 追溯边界

- 出库从当前库存扣减，不默认绑定某张采购申请或某一入库批次。
- 本期要求追溯“谁、何时、什么单、什么物料、多少数量、用于什么、退回多少”。
- 不声称能够定位每件出库物料的采购来源批次。本期不新增FIFO批次分配、序列号、批次成本或物料流向至具体设备；如后续需要另行定义分配规则。
- 品类改变后仍可通过稳定物料ID查到原出库记录，不能因为当前分类不同而切断历史链路。

## 7. 开发设计约束

以下是用于实现本需求的技术设计基线，不代表已有代码、既有API或已验收能力。

开发前先执行第12节的组件复用方案：优先现有公开能力及成熟开源库，不自行实现Excel文件格式、通用权限框架、十进制算法、文件选择器或通用工作流引擎。

### 7.1 模块归属

- 建议新增 `backend/internal/materials/`，统一负责申请、审批、出入库、退库、品类、追溯和单据导出用例。
- 建议新增 `app/lib/features/materials/`，负责五个业务页面及追溯详情展示。
- API与DTO通过现有共享客户端组织；具体文件名在实施时检查项目实际目录后确定。
- 身份、角色、文件存储和数据库能力通过既有公开契约接入。HTTP handler只做解析、鉴权上下文传递和响应，业务规则在Go用例层统一执行。
- Flutter、KP、安卓及浏览器都不直接写数据库，不复制库存余额、剩余可退量和审批状态的权威计算。
- 不为此业务修改采集变量、物理控制服务或现场外部数据库。库存属于独立业务数据，不混入实时测点或报表模板存储。
- 实施前读取当前AGENTS、产品母本、架构及实现／验证约束，核对当前代码和CI；不得把历史交付结果当成本模块验证结果。

### 7.2 最小数据关系

| 数据对象 | 至少需要的稳定关联及事实 |
| --- | --- |
| 分类／物料 | 分类ID、父ID；物料ID、分类ID、名称、规格、单位、预警值、版本 |
| 采购申请 | 申请ID、单号、申请人、当前版本、当前审批状态 |
| 申请版本／审批 | 申请ID、提交版本、正文快照；该版本的审批人、决定、理由、服务端时间及签名快照引用 |
| 入库单／明细 | 入库ID、单号、入库人、确认时间、可空申请ID及批准版本；稳定明细ID、物料ID、数量、单价及档案快照 |
| 出库单／明细 | 出库ID、单号、出库人、用途、确认时间、签名快照；稳定明细ID、物料ID、数量及档案快照 |
| 退库单／明细 | 退库ID、原出库ID、原出库明细ID、退库量、操作人、时间及签名快照 |
| 库存流水 | 流水ID、业务类型、原单ID、原明细ID、物料ID、带方向的数量变化、操作人和时间 |
| 品类转移记录 | 转移ID、物料ID、原分类、新分类、操作人和时间；部分数量方案确定后再扩展数量关系 |
| 凭证／签名资源 | 资源ID、所属单据或用户、类型、内容摘要、受控存储引用；历史单据使用不可变资源版本 |
| 追溯事件 | 事件ID、业务对象ID、版本、事件类型、操作者、时间及关联单据ID；可由已有业务事实投影，避免独立重复写两份真相 |

- 单号用于展示，稳定ID用于关联；姓名和物料名称均不是外键。
- 数量及金额有边界、精度和非负校验；出入库及退库数量必须大于0，合法零单价与未填单价分开表示。
- 操作时间由服务端记录；界面按客户端时区显示，保留可确定的时间排序。
- 列表和追溯明细分页，汇总在后端完整范围内计算，不能把当前页小计标为全单总量。

### 7.3 事务、幂等和并发

- 一次正式入库：单据及明细、库存增加、流水、必要追溯关联必须原子提交。
- 一次正式出库：授权复核、库存足量检查、扣减、单据／明细、流水和签名引用必须原子提交。
- 一次退库：原单归属检查、剩余可退量检查、退库明细、库存增加和流水必须原子提交。
- 审批以当前版本及待审批状态做并发保护，不能产生同一版本两次最终决定。
- 写操作有稳定幂等键，同键同内容重试返回原结果；同键不同内容拒绝，不能再次记账。
- 版本冲突明确返回并保留前端输入，不能静默覆盖另一人修改。
- 图片可先上传到受控暂存区，但正式入库只引用已完成、已校验且有权使用的资源；暂存上传本身不构成入库。
- 接口超时不等于失败。前端用同一操作ID查询或重试，不能换新ID重复提交库存动作。
- 审计及追溯不能记录成功而业务事务实际失败；图片和历史资源不得因更换个人签名被清理。

### 7.4 查询和导出

- 提供按申请ID读取采购至入库链、按出库ID读取出库至退库链、按物料ID读取库存流水的公开用例。
- 支持单号、物料、操作人、时间及状态筛选；服务端在分页和计数前应用授权。
- 接口返回明确状态、正式记录、分页信息和授权内的关联入口，不只返回一段拼接日志。
- 出库单导出使用正式保存的单据快照；记录存在、导出生成成功、用户下载完成分别表达。
- 文件不能公开裸链读取；下载和图片预览再次核验当前身份与原单权限。

## 8. 界面与多端行为

- 桌面沿用项目浅色业务工作区；列表、详情、筛选和操作具有明确层次。
- 申请详情增加“流程追溯”区域，区分提交／审批事件和关联入库批次。
- 入库详情显示来源申请入口或“独立入库”，凭证按整单展示。
- 出库详情显示出库、每次退库和数量汇总；“退库”只对有权限的原出库人开放。
- 物料库存详情可按流水进入原入库、出库或退库单据。
- 手机追溯记录按时间纵向排列，支持展开单据明细、照片预览和返回原记录；不能靠缩小桌面大表完成适配。
- 导出、上传、提交中明确反馈；断网或提交失败保留尚未确认的数据，不能把界面跳转视为业务成功。
- 关键状态同时使用文字，不能只用颜色；无记录、无权限、查询失败分开显示。

## 9. 验收清单

| 场景 | 必须满足的结果 |
| --- | --- |
| 申请驳回修改重提 | 同一申请保留多个提交版本，审批对应版本正确，旧正文和签名不被覆盖 |
| 单级审批并发 | 两名审批人同时处理只有一次最终成功；自审失败，无重复签名决定 |
| 申请关联两次入库 | 从申请能查到两张单及各批明细；从每张入库单能返回同一批准版本 |
| 独立入库 | 可正常入库，来源明确显示独立，不产生虚构申请 |
| 未通过申请入库 | 被拒绝；不改变库存、不产生正式入库和成功追溯事件 |
| 纯文字申请的进度 | 有入库记录后只显示可证明的批次和数量，不自动标全部采购／全部到货 |
| 多物料、多单位入库 | 分物料及单位汇总，不混加不同单位；分页不改变全量汇总 |
| 入库凭证0／1／多图 | 均按规则成功；失败图片不被静默丢弃，历史凭证可按权限读取 |
| 出库5、退库2、再退库3 | 原单数量5，逐次退库可查，剩余可退量3再变0，最终全部退库 |
| 超额或跨用户退库 | 拒绝且无库存、流水及成功事件副作用 |
| 并发出库／并发退库 | 不出现负库存或累计超退；同一幂等操作只记一笔账 |
| 事务中途失败／重启 | 单据、库存、流水关联完整，不出现半条成功链或孤立扣账 |
| 出库后导出失败再重试 | 仅重试文件生成，原单号、签名、库存不变 |
| 个人更换签名／物料改名转类 | 原审批、出库、退库记录及Excel仍使用原快照，追溯链接不断 |
| 权限撤销及手填他人ID | 页面及API均拒绝越权，文件、签名、数量汇总和关联详情不泄露 |
| 跨端使用 | Windows、Web、KP、安卓及手机浏览器状态和数据一致，手机可上传清单照片 |

开发验证优先复用CLI、正常API登录及现有测试；业务测试覆盖事务、幂等、并发、身份范围，UI测试覆盖提交、失败保输入、追溯跳转和移动布局。按项目要求执行Go test／vet、Flutter analyze／test及变更目标构建。真实端、隔离模拟、未执行项分别记录；不通过现场生产操作补测试。

## 12. 开源组件与现有能力复用（2026-11-13核查）

### 12.1 选型结论

本节已核对仓库代码和上游官方文档，尚未安装新依赖、执行组件接入验证或修改业务代码。“已有”表示代码或依赖存在，不表示物料流程已经可用；“候选”需按当前工具链锁定版本后验证。

| 能力 | 选型与状态 | 接入方式及缺口 |
| --- | --- | --- |
| Excel出库单及签名图片 | **直接复用已有Excelize v2.9.1**，BSD-3-Clause | 使用模板、样式及`AddPictureFromBytes`，不用手写XLSX/XML，也不引入在线表格编辑器。仍需实现业务单据模板、快照授权及下载 |
| 数据库与库存事务 | **复用已有persistence、database/sql、pgx、modernc SQLite** | 现有数据库适配层已提供BeginTx及事务内查询。新增物料表和用例，单据、余额、流水原子提交；不用多个SaveConfig调用拼成伪事务 |
| 数量、单价精确计算 | **优先候选shopspring/decimal**，MIT | 提供精确加减乘、指定精度除法及SQL/JSON适配。统一从十进制字符串解析；仍需业务精度、范围、存储策略及舍入约束 |
| 审批状态流转 | **可选qmuntal/stateless**，BSD-2-Clause | 适合状态、触发器、守卫和外部状态存储。若采用，只约束合法转移；数据库事务、版本冲突、签名和权限由物料用例负责 |
| 文件选择与多图 | **复用已有file_selector 1.0.4** | 官方支持openFiles；现有项目封装仅选择单文件，需要增加多选。拍照不是桌面文件选择器自动具备的能力 |
| 图片校验、保存及读取 | **复用设备照片的已有处理方式和标准image/png/jpeg库** | 提取必要的公共能力或通过明确服务契约复用；物料凭证、签名独立归属，不直接调用需要设备ID和设备权限的业务接口 |
| 账号、权限与会话 | **扩展已有identity、authorization** | 加入五项命名权限及资源范围，不另装一套身份或RBAC系统；不能把安全访问日志直接当库存账 |
| 列表、表格与页面布局 | **优先复用DenseTable及Flutter现有控件** | 已有按视口构建行、选择、右键和移动展示。只有明确缺少所需表格能力时再比较data_table_2；不先重写一套表格 |
| 多层分类树 | **优先复用项目现有目录交互；备选官方two_dimensional_scrollables的TreeView** | 官方包也包含TableView。仅在确需树虚拟化／二维滚动时引入，先确认兼容当前Flutter，不顺带重构既有页面 |
| 流程追溯展示 | **既有列表／详情组件，加业务事件投影** | 按单据、操作者、时间和关联流水展示；无需为了两条固定流程引入可视化BPMN设计器或独立流程服务 |

上游依据：

- [Excelize v2.9.1图片API源码](https://raw.githubusercontent.com/qax-os/excelize/v2.9.1/picture.go)、[图片API说明](https://xuri.me/excelize/en/image.html)、[许可证](https://github.com/qax-os/excelize/blob/master/LICENSE)。当前锁定版本已有图片插入API，不为此任务自动升级整个Excel依赖。

### 12.3 安卓与手机上传的实际缺口

目前安卓是[Java WebView宿主](../../mobile/android/app/src/main/java/com/universalhmi/readonly/MainActivity.java)，不是独立Flutter原生安卓应用。检查该宿主代码未发现onShowFileChooser实现。

- 安卓优先使用系统照片选择／相机与`WebChromeClient.onShowFileChooser`接回网页，补URI读取、取消、多选及拍照结果处理。依据：[Android官方API](https://developer.android.com/reference/android/webkit/WebChromeClient)。
- [ReadonlyProxy](../../mobile/android/app/src/main/java/com/universalhmi/readonly/ReadonlyProxy.java)具有方法／路径白名单和请求体上限，普通请求当前为65536字节，设备照片单独放宽。新物料写接口、图片上传和Excel下载需针对性适配，不能仅加页面或全面放开代理。
- 手机浏览器采用文件选择／拍照入口，并按浏览器实际支持提供相册选择；KP及WebView分别验证。不能把桌面选择图片成功等同于手机拍照成功。
- [Flutter官方image_picker](https://pub.dev/packages/image_picker)是成熟候选，但并不能替当前Java WebView补文件回调。只有实际Flutter原生端需要时再引入；桌面相机也不由该插件默认提供。
- 个人签名按需求是上传图片，复用同一图片能力即可；不引入手写板、第三方电子签约平台或证书签名产品。
