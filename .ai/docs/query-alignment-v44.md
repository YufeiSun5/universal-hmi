# 查询按钮位置与等高修正 v44

产品母本为[agent.md](../../agent.md)，当前状态见[唯一看板](../../AI_BOARD.md)。

## 范围与行为

用户指出v43按钮固定另起一行、未靠最右侧，并要求按钮与下拉框等高、上下对齐。本批仅修改Flutter公共查询布局及发行版本。条件使用原有Wrap实际排版结果；按钮组测量自身宽度后，优先放入最后一行的右侧空位，放不下才另起一行靠右。最多三行，超量条件页内滚动，主操作保持可见；短横屏条件在左滚动，操作在右。数据、权限、查询接口和移动左侧目录/底栏保持原契约。

不改变条件与操作之间的组件身份以适配普通宽度变化。测量在渲染布局阶段完成，不依赖硬编码字段数或事后setState跳动；输入与下拉框的可见边框和按钮表面按同一控件高度及行中心对齐。

## 本轮验证

新增实际绘制边框检查：1000/430/620宽度下，输入、下拉与按钮的高度相同；同排上/下边缘一致；按钮右边缘贴查询栏内边；第二行有余量时不制造第三行；改变宽度后输入保持。桌面34px、触屏44px的既有主题保持。

35项查询、弹窗、历史滚动回归通过；Go全量test/vet、Flutter完整586通过/2项既有浏览器专用跳过、analyze无问题、249文件只读格式检查通过。首次完整回归发现短窗次操作排到条件之后，导致登记/清除初始不可见；已将操作整体放到右侧，保留原用例及断言复验通过。

实际Chrome已确认历史宽屏一行、900×600窗口两行，查询按钮位于当前最后一行右端并与控件边框齐平。最终WebAssembly、Windows完整安装包、同签名APK及v43→v44保数据验收待完成，后续回填最终截图、文件摘要及CI。

现场、18153和用户工程未改。隔离SQL、合成配置与统计显示夹具各自记录；不把浏览器模拟手机当作安卓真机验收。
