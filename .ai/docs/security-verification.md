# 多用户与站点权限实施验证

2026-10-27；用户最终要求为“工程师可以开发，其他用户不能开发”。产品母本见 [agent.md](../../agent.md)，权限合同见 [architecture.md](architecture.md#2026-10-27-联网安全与用户权限)。这是当前工作树的本机实施记录，不是公网部署或安全认证结论。

## 本批实现

- `backend/internal/identity` 持久化用户、稳定站点ID和审计；Argon2id密码，按2026-10-27用户最新要求本机5–128字符、公网7–128字符（替代首版15位下限），有限常见口令拒绝、限流、最多两个并行密码计算。首次管理员由用户自行设置，没有内置密码。会话仅存摘要，8小时绝对期、30分钟空闲期；自动实时刷新不续空闲期。重启失效，禁用/改权限/改密码撤销旧会话。
- `backend/internal/authorization` 定义共同Actor、角色、站点及额外画面授权；HTTP、MCP、业务用例和后台动作共享检查。当前全局开发需要工程师+全部站点，用户管理需要管理员+全部站点；单独管理员无开发权。控制、授予控制和数据文件能力单独表示。初始账号同时具有管理员/工程师/审计员角色，但没有设备下设权。
- `points/runtime/storage/process/navigation/analysis` 按范围读取；实时/SSE、历史查询统计、菜单、GIS引用和目标跳转均裁剪。共享画面授予其静态内容访问，不附带跨站变量权限。非工程师不能读取公式和来源凭据等开发内容。
- 上传/导出任务绑定用户和权限版本；排队执行、下载再次检查，猜测ID不能取得别人文件。受控写入在发送前复核，撤权后的排队动作记录未发送；已发送动作仍按原发送/应答/读回契约处理。规则使用显式发布人的受限执行身份，账号撤权阻断新动作，普通退出不停止共享采集和独立存储。
- TOTP绑定、验证码防重放、一次性恢复码、修改密码、会话撤销、管理员重置MFA；TOTP密钥加密落盘，密钥文件及数据库目录受Windows ACL/Unix权限保护。远程模式要求实际TLS及MFA，未绑定时只能进入绑定流程；显式本机模式允许回环HTTP试用。
- KP正式身份可与 `--identity` 组合；既有稳定subject映射到预先创建的user_id，可信verifier提供MFA及认证时间，旧operator不产生工程师权。业务请求同时检查KP实例和统一会话，任一撤销即拒绝。回环用户名试验模式不能与统一身份混用。
- Flutter提供首次建号/登录、账号安全、用户角色和范围管理；普通用户进入监控端，管理员管理入口独立于开发工作台。桌面自启统一身份服务；健康检测拒绝复用旧匿名服务，端口冲突仍使用安全回环回退。

## 固定入口与操作

评审入口继续使用 `http://127.0.0.1:18153/`，沿用 `.local/gis-editor-preview/data`。程序/静态资源保留旧版本，升级前SQLite在线备份并验证完整性，对原JSON和SQLite逻辑内容做前后摘要比对。新增 `security/` 是身份库，不改写旧点位、画面或历史。详细状态见 [部署记录](evidence/20261027-security/deployment-18153.json)。

第一次打开新版由用户设置初始账号及长密码，然后通过“用户与权限”创建普通账号并选择站点/额外画面。站点范围用于数据授权，画面上的人工文字属于画面内容，应在额外共享前审阅。工程师全局开发须同时选全部站点；普通管理员需要同时显式拥有工程师角色才能开发。

联网部署须先本机完成首账号设置及MFA，再停用本机引导模式，以 `--identity --public-origin https://明确主机:端口 --tls-cert 证书 --tls-key 私钥` 启动；不把本机HTTP服务通过代理公开。具体证书、监听、KP verifier和账号配置属于AUTH-DEPLOY，不自动代填。

## 明确剩余边界

这是单工程的第一版安全基线。Passkey/WebAuthn、OIDC、邀请邮件、联网泄露口令库、按端类型发放权限、局部工程师发布、双人审批、独立服务账号管理、完整CSP来源策略、外部不可篡改审计及轮换/容量告警、自动加密备份恢复演练、代理信任链与实际网络渗透/压力验收仍未实现或未验收。当前审计为同机SQLite，MFA加密密钥与数据库同机，不能冒称防主机管理员篡改或独立密钥托管。旧单账号及KP试验入口保留兼容，但不属于本批统一身份部署方案；既有18139试验服务未替换。后续工作在唯一看板跟踪，不以本批passed代替这些条件。
