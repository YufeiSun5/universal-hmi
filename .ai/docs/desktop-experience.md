# PC 优先的现代工作空间

需求来源：[agent.md](../../agent.md)。以下是设计/验收目标，工程骨架不代表全部完成。

## 参考与交付原则

参考 VS Code 的工作空间导航、标签/命令操作、可调整面板、快捷键和状态栏，参考 Figma 桌面端的中央画布/属性区及精准指针操作。复用交互原则，使用自己的视觉系统。

Flutter 是 desktop/web 的 UI 框架；不以框架名声称“原生品质”。桌面必须实际验证窗口、文件、焦点、键盘、鼠标与 DPI，而非只用网页截图验收。

## 布局与视觉

- 导航：工程/站点、点位、事件规则、存储、分析与导出。
- 中央工作区优先容纳密集表格/图表；属性区按需展示当前选择，不挤满无关卡片。
- 侧栏、属性栏和图表区域可调整，记忆有效布局；小窗口退化仍可操作。
- 状态栏展示后端连接、数据陈旧、存储积压和任务状态，避免把错误只藏在日志。
- 浅色/深色共享语义 token；字体、行高、边框、间距、焦点和状态色统一。
- 信息密度可配置；状态不只靠颜色。避免装饰性留白、巨型卡片与过度动效。

## 可执行验收清单

| 交互 | 验收方法 |
| --- | --- |
| 数据添加 | 键盘完成打开/填写/提交/关闭；验证错误不丢已填内容；刷新后读取保存项 |
| 点位表 | 固定表头、长名称、横纵滚动、列宽调整、选中/批量操作；用代表性大数据验证虚拟化 |
| 搜索筛选 | 条件可见、可清除、状态可保存；表格、统计、图表与导出条件一致 |
| 快捷键/焦点 | Tab/Shift-Tab/Enter/Esc 可预期；命令搜索；Ctrl 在 Windows、Meta 在 macOS；冲突不阻止文本编辑 |
| 面板/窗口 | 1280×720、1920×1080，100%/150%/200% DPI；调整面板与缩放后没有不可达按钮 |
| 图表 | 游标、缩放、平移、区间选择、多曲线与表格联动；缩放不与父滚动争抢 |
| 文件 | desktop 原生文件选择/保存，Web 上传/下载；取消不产生假成功 |
| 主题 | 两种主题对比度、焦点、选中、禁用、错误、空态和长文本逐项检查 |
| 后台/离线 | 页面切换或浏览器断开不停止后端；陈旧值明确标记，不冒充实时正常 |
| 异步任务 | 排队/运行/完成/失败/取消及部分成功可见；重连恢复任务状态 |
| 平台一致性 | desktop/web 用同一用例结果；原生能力缺失有明确替代，不静默失效 |

第一版骨架只实现导航、主题、连接状态及基础点位配置流程；面板调整、快捷命令、图表和文件操作按看板推进。性能数值依据总点数、样例与测试环境建立基线，不捏造帧率保证。
