# 隔离双监听 HTTPS 验证

[小型证据摘要](smoke-summary.json)记录真实 server.exe 在随机回环端口、独立 SQLite 工程上的验证。测试脚本为 `ci/public_remote_smoke.py`，可传 `--server` 使用最终包内二进制；默认用固定 Go 1.24.7 构建到新的 `.local/public-remote-*` 目录。测试自签证书仅该目录、127.0.0.1、一小时有效，未更改操作系统信任。

通过本机首次建号、实际 TLS 登录与 MFA、授权读取、工艺图和图片素材保存读回、手工点 42.25 的 SSE reset，以及未认证/错 Origin 拒绝、仅本机部署摘要和双监听优雅关闭。另使用 20 个独立 Connection: close 请求重复验证带 body 的 401/403，无请求重试。

旧构建在相同拒绝循环断连，新构建经有界读取修复后通过；失败目录保留。脚本自身停止事件句柄覆盖错误已独立更正；不把该脚本错误记为后台锁故障。临时诊断源码已删除，正式构建没有调试端口。

本轮不代表真实公网、路由映射、Windows 防火墙、浏览器人工接受自签警告、PostgreSQL 服务安装或现场设备验收。以上隔离测试未操作固定 18153 或真实工程；主代理随后执行的本机升级另见 [部署证据](deployment.json) 与 [验收记录](../../public-remote-verification.md)。

最终补充真实 TLS 截断/慢 body 回归：分别声明 1 KiB、128 KiB，仅发送一个字节，错误 Origin 的完整 403 必须在三秒内返回。仅完整读取的小 body 清除读截止时间，其余关闭连接并保留立即截止时间。最终 Go 全测、vet 和独立二监听 smoke 均通过。
