# 历史报表、全时段曲线与 MCP 可见控制

本轮由用户实际评审提出：500变量站点的历史报表/曲线需要更实用，并需要可见的MCP模式开关与连接测试。母本仍为 [架构](architecture.md)；不是另起应用或重新初始化。

## 历史查询的合同

- 历史页进入会自动查询。默认预设由实际客户端时钟生成，显示本机 UTC 偏移；15分钟、1小时、24小时、全部及手工日期时间均转为UTC epoch毫秒请求，不使用助手的会话时间替代数据时间
- 手工时间应严格拒绝不存在的月日/时分秒，不能把2月31日默默变为3月日期。开始晚于结束时拒绝查询
- 500点站点使用可搜索选择器，曲线比较最多6个稳定点位ID。单点兼容原point_id，多点采用point_ids；不能混用、重复、空白或突破数量上限
- 原始样本仍分页（1000行）；完整曲线使用独立 `/api/v1/history/series`，每点预算20–600、返回不超过该预算的真实原始样本，全请求最多6点；不是读取第一页冒充全时段
- 图形输出保留首尾/极值与质量断点、冻结站点/单位/配置版本。短暂语义变化也必须在图形中可见；输出预算或语义组上限无法容纳时明确失败，不悄悄忽略历史。汇总组最多256，查询有3秒期限
- 同一source_time按持久seq及稳定输入顺序排列，避免重复采样乱序将断点移动。不同单位分开显示，不能以当前配置覆盖旧单位或旧版本
- 完整曲线、相关统计、原始分页和导出共享已应用筛选及冻结before边界。未应用的输入编辑不能带旧offset/before直接翻页或导出；从曲线转入报表不重新计算相对时间或切换快照
- 未选择具体点位时全站原始分页和导出仍可用；变量统计明确标为当前页范围。选1–6点后才提供全范围冻结单位/版本汇总，不能把一页数据称为500点全量统计
- 导出仍为原始筛选范围内的数据，不导出降采样曲线点冒充完整历史。异步任务冻结多点选择数组

## MCP 控制合同

新增设置页显示端点、模式、有效权限与工具数量；实际连接测试经同一客户端向 `/mcp` 执行 initialize、tools/list 和只读 health_get，不下设设备、不创建账号或token。细节见 [MCP合同](mcp-coverage.md)。

每次进程启动只读。off/read_only/write仅作用于本次运行，不持久化；write同时需要启动 `--mcp-write` 上限、账号写权限和显式应用模式。模式管理通过独立、同认证/CSRF保护的设置API，不作为MCP工具；存在版本竞争时要求刷新，不自动重试修改。关闭或只读不会撤销已经受理的设备命令。

本轮验证只使用隔离合成数据和既有测试账号；不部署真实内网，不开公网端口，不生成真实持久凭据。Windows/macOS人工UI及真实现场数据不是本轮自动测试可以替代的证据。
