# 外部小时报重点曲线 v94

## 范围与入口

历史目录中，每个已授权小时报旁派生“重点数据曲线”，KP、Web和Windows共用。默认北京时间今天、站区列表首项；可逐项增加/取消，也可一键全选。选择应用后查询；日期支持包含首尾日期的区间，沿用统计库2026-11-04起、最多31天的边界。一次最多256站、200000个重点测点返回样本、30秒服务查询预算，超限明确报错，不截断全选结果。

上图一次网/二次网热量为小时报的小时用量，不使用累计表底；下图二次网供回水温度、压力为每小时最小～最大区间柱，温度左轴、压力右轴。图例可逐项显隐，时间滑条、图内滚轮和拖动平移联动两图；恢复完整视图重置时间范围。

## 实现边界

- `externaldata`复用原小时报查询、权限、来源连接和六参数统计存储过程。固定六个实际PointCode通过Point和统计宽表列配置映射Value列，不按名称猜测、不固定Value序号。站区每批8项逐日读取，全部选择均参与。不同量纲分别成轴，同组不同单位拒绝误叠加；℃/°C仅统一字形。零值、缺值、质量和原始十进制字符串保留，提示框显示原始精度。
- Flutter派生入口继承原小时报`query_id`，不是新授权画面。宿主只接受站区列表、固定key_trends查询消息，原画面路径和请求mode由宿主确定；渲染器不获取凭据、不选择任意API。查询返回前再次校验原画面读取权限。
- 复用总报表嵌入宿主，新增独立消息channel和资源目录，不改总报表默认行为。KP只增加精确的key-trends静态入口，原认证和API准入不变；Windows复用只读资源代理。
- Apache ECharts 6.1.0锁定依赖并随包离线提供；缩放、图例、提示框、坐标轴由ECharts处理。高低柱通过官方[custom series](https://echarts.apache.org/handbook/en/how-to/custom-series/)绘制上下界和端帽，不伪造开盘/收盘值。源码和依赖配方在`tools/key_trends`，运行`npm ci`、`npm run build`生成`app/web/key-trends`；随包附许可证和依赖摘要。

不改小时报原有数据，不修改存储过程或外部数据库。新功能的后端测试使用隔离sqlmock，浏览器截图使用合成小时报数据；这不等于真实SQL Server、真实KP宿主、Windows WebView人工及现场数据验收。
