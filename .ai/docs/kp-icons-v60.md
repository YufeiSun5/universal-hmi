# KP顶部图标兼容 v60

用户反馈正式KP嵌入页的顶部PNG导航图标只剩细线，右侧Material按钮和工艺图片仍正常。用户随后确认退出已能返回KP登录页，本批仅处理图标，不修改退出、脚本、认证或权限。保留v59的私有IP HTTP正式核验能力。

## 修改

`MonitorHeader`顶部图片在Web端不再传入`cacheWidth: 144`，避免额外的CanvasKit解码缩放及中间图片纹理；仍从原PNG加载，在绘制时缩到原48×48尺寸。普通页灰蓝滤色、选中原色、GIS原样式、标签和点击位置保持。Windows原生端仍使用144px解码缓存。没有修改原PNG、工艺素材或工程配置。

这是针对相关图片加载路径的兼容修订，不把尚未复现的现场故障归结为已证实的浏览器缺陷。六种顶部图标在Web端按原1254×1254解码，估计RGBA像素内存由约0.5MiB增至约36MiB，图片缓存仍复用；网络资源体积不变。

上一版文档head `99a33e1` 的四端Flutter CI因`test/kp_ui_test.dart`格式检查失败。本批仅格式化该断言，行为不变；不将此前CI记为成功。

## 验证与边界

修改前已在KingPortal自带Chromium110.0.5481.178加载v59隔离工程，分别使用可信回环HTTP父页面和非可信HTTP父页面（`isSecureContext=false`、无ImageDecoder），均未复现现场细线。该结果不代表现场已经正常。后续候选/最终产物检查与保数据验证结果交付时回填。

使用正常API登录隔离账号设置联调入口；模拟父页面仅用于嵌入渲染验证，不作为真实KP身份或正式退出验收。没有部署现场、修改18153或改动用户工程。最终现场图标仍需在更新后确认。
