# 数据源变量扫描验证 · 2026-10-26

本轮实现用户要求的选择数据源扫描、关键字过滤、类型识别和批量添加。产品要求见[agent.md](../../agent.md)，技术合同见[架构](architecture.md)及[协议](protocols.md)。不代表现场 KingIO 服务已验收。

## 已实现

- 变量设置「扫描添加」、手工新增框「从数据源扫描并批量添加」、采集来源行「扫描变量」三个入口共用对话框。
- 选择来源及目标站，显式连接后读取扫描目录；支持关键字过滤、每页200项、修改名称/类型、全选本页、已有映射标记和一键原子保存本页选中项。
- KingIO 首次全量包在点位映射之前捕获，零配置可发现；generic/Kepware沿用同一解码观察入口。源连接保留，8秒窗口只控制UI刷新。
- BOOL/STRING/FLOAT按JSON值推断。数值默认FLOAT，可选INT；未知/冲突需用户确认。保存默认只读、倍率1、偏移0，仍需独立应用运行配置。
- 目录全引擎20000项、结果分页最多500项、样值最多256字节；质量/源时间/保留标记及丢弃/解码诊断保留。断开/重连清空对应目录，旧连接回调不能重新填充。

## 部署与边界

更新本机18153预览的Go服务与Flutter Web，保留原GIS静态资源；复用原数据目录，配置/画面JSON摘要前后核对。更新前没有已连接来源、demo或启用的存储策略。用户原浏览器页面不自动刷新，已有页面须先保存草稿再刷新使用新入口。

仅捕获协议合法且实际收到的变量。未发布变量、厂商未提供值的对象、超过单包10000项限制或解析失败的报文不构造虚假结果。目录不持久化，也不把扫描样值回放为新鲜运行数据；应用后正常采集仍遵守源时间/质量和后续消息语义。真实厂商版本、实际broker与现场全量发布条件仍需现场验证。旧CI不覆盖本轮未提交工作树。
