# KP 空核验地址联调 v53

用户已明确要求“不补齐允许也能用”：本地KP在用户电脑，监控后台在服务器，暂时无法回连时仍需嵌入页面联调。此前仅允许保存草稿不能满足该需求。本批增加固定测试账号的受控联调，保留正式核验作为另一种模式；[架构合同](architecture.md#kp-受控联调与草稿2026-11-06v53)定义认证边界。

## 实际操作

1. 升级监控服务器软件，在开发态打开“登录与安全 → KP 接入”。
2. 打开启用开关，选择“联调模式”，搜索选择一个具有所需站点、画面和读取权限的固定测试账号。
3. KP网页来源填实际浏览器地址。例如KP在同一用户电脑通过`http://127.0.0.1:11005`打开，则填这个来源。后台服务地址可以留空；无需填写正式KP用户映射。
4. 点击“保存配置”，再“应用配置”。显示“实际状态：联调模式／未核验 KP 身份”和固定测试账号，即配置已应用；公网HTTPS仍须正常监听并满足既有设备/IP准入。
5. 脚本区域填写监控HTTPS地址与网页容器名称，复制“画面打开时”和“画面关闭时”脚本到KP对应事件。打开脚本携带只绑定该测试账号的临时授权，KP容器直接进入只读页面，页面上方显示联调状态。它不依赖KP后台核验地址或本地KP令牌。
6. 每次重新应用配置或后台重启后重新复制最新打开脚本，旧授权和旧关联会话失效。联调模式的关闭/退出只撤销联调会话，不调用KP账号LogOff。
7. 正式联调准备好服务器可达的KP核验地址后，切换“正式核验”，填地址与KP稳定用户ID映射，保存后应用；旧联调授权不能继续登录。

当前监控入口`https://124.93.137.40:9090`与用户本地KP来源是不同地址。联调授权由管理员明确授予固定测试账号，不表示验证了KP登录身份；客户端传入用户名不能选择其他监控账号。账号、站点权限、设备准入和公网只读继续有效。

## 状态

保存草稿可缺字段；正式核验缺地址时显示“待完善”，可改为联调模式并选择测试账号后应用。字段格式错误、账号失效和版本冲突仍明确拒绝。失败时保留当前已生效配置，页面显示实际运行的模式、地址或固定账号；重新读取失败不冒充已刷新状态。
