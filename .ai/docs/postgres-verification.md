## 实现

- persistence 提供 pgx v5.7.5 的 PostgreSQL 方言、完整文档存储、单后端会话锁及一次性迁移。历史/运行配置归 storage，账号/角色/审计归 identity，点位及画面继续由各自领域服务校验。
- 本机 Docker PostgreSQL 18.2 使用新建专用 `universal_hmi` 库及非超级用户账号。既有 scada、resonance 等库未改。连接配置仅保存在本机私有目录，程序包不包含凭据。
- 配置了 PG 后连接失败拒绝启动；测试证明不会悄悄生成 SQLite。SQLite/JSON 保留为兼容适配和迁移来源；历史查询快照、画面 revision、身份及 MFA 密文迁移保持，MFA 密钥仍属于本机受 ACL 保护的目录。
- 开发态提供“权限配置”。“用户与权限 → 角色管理”支持自定义岗位名称、功能权限、成员搜索/批量分配，以及无成员角色删除。用户编辑可组合预置角色和自定义角色。
- 自定义角色提供功能权限，用户的站点/额外画面范围独立保留；有效权限为直接权限和角色权限并集。工程师开发及用户管理仍需全部站点。服务器检查授权上限、自身权限修改、账号/角色版本及最后管理员，角色变化原子重算成员授权并撤销旧会话。已分配角色删除被拒绝。
- 运行态/开发态有独立 SVG/PNG/ICO 图标。共享工程启动脚本检查实际监听进程并复用固定18153；入口仅选择界面，不授予开发能力。
