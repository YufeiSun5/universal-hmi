# KP内网HTTP核验 v59

用户现场KP后台为172.16.1.8:11005，原版本在保存阶段仅允许HTTPS或本机HTTP，导致invalid_kp_server。本批明确支持管理员配置的私有IP HTTP，Windows/Web更新，保留v58已有线上运维和报表能力。

## 合同

KingPortalVerifier允许HTTPS；HTTP允许IPv4 RFC1918、IPv6 ULA及既有本机回环地址/localhost。公网IP、非localhost域名、链路本地地址、未指定地址和共享地址空间不因本次修订放开HTTP。配置不能带用户信息、路径、查询或片段；请求仍固定/api/v1/getUserInfo，不跟随重定向，保持超时/响应大小/并发限制。权限、账号映射、设备/IP准入和令牌验证不变。UI说明内网IP HTTP用法，invalid_kp_server返回明确地址错误，不再笼统指向工程名/重复用户ID。

## 验证

私有IPHTTP专项覆盖172.16.1.8、10/8、192.168/16与IPv6 ULA的实际Verify调用（受控transport），核对固定目标和令牌头、以服务端返回身份为准以及无效令牌拒绝。原重定向不转发凭据测试保持，补充私有网段边界/链路本地/公网HTTP拒绝。

真实管理API测试覆盖保存、应用172.16.1.8:11005并读回实际地址，失败配置不替换已生效配置；Flutter沿用原草稿到保存/应用流程改用该地址回归。Go全量test/vet、Flutter analyze与630项通过/2项既有跳过，Windows/Web同源构建通过。v58→v59隔离覆盖、重装和卸载保持5019变量、31画面、12业务表及账号、图片、批准证书、价格、菜单、来源/绑定和KP配置；原快捷方式恢复，隔离端口停止。

接手核对发现v58的四端CI均因旧kp_ui_test期待“只读”文案失败；v58已按用户授权开放命名运维能力，实际banner仍明确“联调模式/未核验KP身份”，测试本次同步正确文案，保留账号和未核验标识的精确断言，不修改运行权限。

## 现场边界

此前独立Go进程已用生产KingPortalVerifier请求本机真实KP，当前令牌返回已知身份、伪造令牌被拒。现场172.16.1.10到172.16.1.8:11005只收到用户提供的TCP可达结果，端口服务身份、真实账号映射整链路和长时间令牌刷新仍待现场验证；本包不冒称已经部署或连通现场KP。
