## 调研依据与实际缺口

外部交互依据：GOV.UK [输入标签与提示](https://design-system.service.gov.uk/components/text-input/)及[错误摘要](https://design-system.service.gov.uk/components/error-summary/)要求将提示与输入建立明确联系，并能从错误摘要定位字段；Carbon [空状态](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)强调说明空白原因并提供下一步，[筛选模式](https://v10.carbondesignsystem.com/patterns/filtering/)区分即时单选和批量提交筛选。这里借鉴交互原则，保持现有产品视觉规范，不照搬其页面外观。

## 已明确的用户要求

1. 品类增加删除功能；默认进入时能看到展开的树形结构。
2. 物料模块左侧提供品类树，用于快速筛选。
3. 用户可设置自己的登录首页。
4. 没有访问权限的页面不显示任何菜单入口。
5. 入库、出库按时间段查询；上面显示该时间段概览，下面逐单展示。
6. 改善用户填写与点击过程，提供具体、可理解的引导。

现有约束继续适用：物料手机入口本期隐藏；原单、历史金额、签名和库存账不因目录调整漂移；不改现场或 18153。

## 建议交互与业务规则

### A. 品类树与删除

界面明确区分“分类”（树节点）和“物料档案”（名称、规格、单位、单价）。分类树在品类页默认显示并展开；提供分类搜索、全部展开/收起、新建根分类、添加子分类、重命名、删除。点击名称只选择节点；展开箭头只展开，不把点击筛选同时变成编辑。

首次进入展开已有各级分支；用户手动收起后在当前会话保留选择与展开状态。大型树渐进加载，明确显示正在加载和加载更多，不用第一页冒充完整分类树；搜索显示命中节点及祖先路径。

建议删除采用逻辑删除并提供“已删除”查看/恢复，历史查询仍能解析旧 ID。删除前显示对象全路径、影响范围以及阻止原因；正式提交再在事务内检查，避免预检后新增业务造成悬空引用。

- 分类仍有有效子分类、在用物料档案或非零库存时不允许直接删除，显示具体数量并提供跳转处理；不自动连带删除子树、物料或库存。
- 本轮明确补充分类节点删除，不另行扩大到物料档案删除。已删除分类不能作为新业务目标；旧出库的合法退库继续从原单办理，选择有效目标分类，保留原单与分类快照。
- 已删除资料不出现在普通新业务选择器中；历史单据和日志保留原快照。删除、恢复、重复请求、并发提交均使用现有权限/版本/幂等规则。

用户指出的是“品类现在只能创建、不能删除”的现状缺陷；补充品类删除为明确要求，不再列为是否实施的待选项。

### B. 物料模块整体布局

| 左侧同一栏 | 右侧工作区，从上至下 |
| --- | --- |
| 上部：有权业务菜单 | 页面名称、简短用途说明、主操作按钮 |
| 下部：分类搜索、“全部分类”、展开的分类树 | 常驻时间段与查询条件；当前分类完整路径 |
| 选中高亮，长名称可查看全路径 | 当前筛选范围的概览 |
| 可收起，内容独立滚动 | 逐条记录、明确的“查看详情”或编辑操作 |
| 分类页直接提供节点管理操作 | 数字分页与跳转 |

分类树用于档案、库存、入库、出库、操作日志。选父类默认包含全部子类；切换分类自动查询并回到第一页，保留日期、搜索等其他条件。面包屑与筛选标签显示当前范围，支持一键清除分类。业务页之间保留当前会话的分类选择，避免来回查找。

纯文字申请没有结构化分类，不对无分类申请套用虚假的分类筛选；申请审批页隐藏分类筛选区。仅有申请/审批权限的用户不因此获得物料目录、金额或库存读取权。

新建分类、档案和入库行可带入当前选中分类，但不得静默修改已有草稿的物料或入库目标。历史单据依据实际行分类匹配；档案的默认分类改变不会改变旧单归属。

### C. 时间段查询、概览与单据

入库、出库把日期放到常用查询区，不再藏于更多筛选。建议首次默认本月，提供今天、本周、本月、上月、自定义和全部；自定义范围选完后点击查询，日期开始晚于结束时就地提示，不发送无效请求。保留上次当前会话条件，顶部明确显示实际查询范围。

业务日期统一按北京时间解释，起始日 00:00 至结束日下一天 00:00 前；跨时区客户端查询同一个业务日应得到相同范围。默认采用单据正式生成时间，不在本轮悄悄新增可补录的业务日期。

| 入库概览 | 出库概览 |
| --- | --- |
| 入库单数、涉及物料种数 | 出库单数、涉及物料种数 |
| 入库数量，按单位分别汇总 | 出库数量，按单位分别汇总 |
| 已知入库金额、缺价行数 | 已知出库金额、缺价行数 |
| 可查看按物料汇总的明细 | 本期发生的退库数量/金额单独展示，并可切换查看退库单 |

数量不能将“个、米、吨”等不同单位直接相加。缺价不能当零，金额沿用单据冻结值与精确十进制口径。

概览统计全部符合条件且有权的数据，不随页码变化；列表和概览由相同过滤条件、同一一致性快照产生。分类筛选命中单据的部分行时，概览只统计命中行；列表同时注明“该分类小计 / 整单金额”，详情仍展示完整有权单据，避免看似金额对不上。

本期退库按退库发生时间统计，可关联此前月份的出库；“本期退库”与“本期出库单截至当前的累计退库”分别命名，不混算。建议暂不把不同选择范围的金额直接相减为一个无说明的净额；需要净出库时明确标注是本期发生口径并列出构成。

无结果时显示“该时间段和分类下没有入库/出库单”，并给清除筛选、调整时间或新建单据的入口；加载失败与真正的零记录分开显示。

### D. 本人登录首页

在本人账号设置中增加“登录首页”，仅列出有访问权限、已配置且当前终端支持的页面；可选择物料模块下具体有权页。选择后保存到本人账号，重新登录生效，并可“立即打开”。

用户已确认：一个账号只保存一个首页，跨终端共用；当前终端不支持时自动回退。回退只影响本次打开，不覆盖账号原首页。手机候选不含本期关闭的物料页面；若账号已在电脑设置物料为首页，手机设置页仍说明当前选择及本端回退去向，不把原选择显示为空或静默改写。

跳转优先级：用户明确打开且有权的业务链接 → 本人有效首页 → 当前终端有权默认页。KP明确指定的嵌入目标不能被个人首页替换。首页被删除、停用或撤权后回退到首个可访问页面，并简短提示原因；没有任何业务页可访问时进入账号/权限说明页，避免循环跳转或空白。

### E. 全系统菜单权限

统一核对顶部菜单、左侧树、手机底栏/更多、快捷切换、卡片快捷入口、首页设置候选和直接链接。无访问权限隐藏；有读取权但无编辑权保留只读页面、隐藏编辑操作；临时加载状态可以禁用并说明原因。

后端按现有角色、站点/画面授权、业务能力与模块配置生成页面可访问集合，各入口复用该结果。权限不足与有权但尚无数据分开判断，不因列表暂时为空误删正常入口。外站、历史/能耗/总表等结合实际可用配置和现有范围判定，不能只把有无写权限当作页面访问权。

当前模型并没有每个一级页面独立授权开关。本轮先落实“无权不显示”；如还需要管理员单独指定“允许总览但不允许历史”，须明确新增模块级访问授权及旧账号迁移策略，不能仅添加前端开关冒充权限控制。

撤权后导航和首页候选及时刷新，正在访问的页面停止后续操作并退到有权入口；手输链接和直接 API 仍由服务端拒绝。个人偏好不能授予任何新权限。

### F. 填写与点击引导

全系统盘点用户需要点击、选择或填写的入口；本次先完成物料六页、个人首页设置及导航权限相关页面，其他现有业务页发现的问题逐页列入清单。

- 表单按任务分区：先选择业务对象，再填明细与用途，最后核对并提交。复杂入出库使用有步骤提示的宽表单，支持返回修改；不强制为简单分类重命名增加向导页。
- 每个输入保持可见标签，区分必填/选填；数量旁显示单位、允许精度和范围，入库价说明仅影响本单，出库价说明取档案快照。
- 出库选择时直接显示各分类可用库存，填写后显示预计剩余；退库显示原出库量、已退及本次最多可退；转类显示来源、去向、两边变化。
- 缺分类/物料/签名时明确说明下一步。有相应权限提供创建或设置入口，无权则说明需要哪个业务权限；返回后保留草稿和已填内容。
- 表单提交前校验必填与明显格式错误；错误同时显示在字段旁和可定位摘要中，定位到第一个问题。服务故障、冲突、权限变化分别给出可执行的下一步，不只弹一个技术错误。
- 主按钮使用明确动作：“下一步：核对出库”“确认出库并扣减库存”“确认入库并增加库存”。次要操作使用“返回修改”“保留并关闭”；明确当前草稿只保留本次登录会话，不能称为已保存到服务器。
- 成功后展示单号、操作结果及“查看单据 / 导出 / 继续新建”。提交超时显示结果待确认并按原操作重试，避免用户误以为失败后重复记账。
- 图标按钮有可见名称或稳定提示；查看详情入口明确。空白页、无匹配结果、没有权限、加载失败使用不同文案与动作。

## 实施顺序与模块边界

| 顺序 | 工作 | 主要路径与公开契约 |
| --- | --- | --- |
| 1 | 依据已明确规则，形成品类页、出入库页、填写步骤和首页设置的界面样稿，逐页评审 | 本计划及现有桌面设计规范；先确定用户操作路径 |
| 2 | 分类删除规则、树查询及子类过滤、单据分类过滤与全量概览 | `backend/internal/materials/`；`server/materials.go` 仅做请求/响应；新增契约同步文档 |
| 3 | 账号首页偏好与统一页面访问集合 | `backend/internal/identity/`、`authorization/` 与会话响应；前端不重新推导独立权限规则 |
| 4 | 左侧分类树、日期常驻、概览/列表、分步骤表单及各状态引导 | `app/lib/features/materials/`；复用共享表格、日期与分页组件 |
| 5 | 登录跳转、全系统入口权限、个人设置 | `app/lib/main.dart`、账号设置、`process/monitor_chrome.dart` 及各导航入口 |
| 6 | 按用户任务实际操作、截图复查，再做兼容与发布 | CLI/API/widget/浏览器优先；无需为测试身份反复操作桌面登录框 |

不改采集变量、物理控制、现场历史库或财务成本模型。新增数据字段采用 SQLite/PostgreSQL 兼容迁移，保留旧档案、原单、库存与账号配置。公共 HTTP/KP/Android 路由只同步必要公开接口，不扩大通配写入范围。

## 可验收的完成条件

1. 新会话打开品类即可看到展开的树；超过50个子节点、多层同名分类、搜索定位、手动收起与刷新均可用。
2. 删除前准确列出阻止原因；并发新建子类、增加库存、重复点击及失败重试不产生悬空引用；删除/恢复不改历史金额或签名。
3. 左侧父分类能筛出全部子类，切页、切业务页、清除分类和历史快照匹配一致；纯申请角色不能读取不应获得的目录和金额。
4. 时间筛选覆盖跨月、边界午夜、跨时区、空范围、非法范围；概览不随分页改变；混合单位、缺价、零价、跨期退库和单据部分分类匹配均有明确结果。
5. 首页重新登录及同账号跨终端同步生效；撤权、删除目标、手机禁用模块、直接链接、KP嵌入和无可访问页面均有稳定行为。
6. 使用只有申请、只有入库、只有出库、只有档案、普通只读、工程师/管理员等账号，逐个核对全系统菜单与直接 API；页面读取权限与编辑权限分别验证。
7. 新用户无口头指导即可完成：新建分类和物料 → 入库 → 按分类/时间查询概览 → 出库 → 退库 → 查看原单；遇到缺签名、无库存、输入错误和网络超时都知道下一步且不丢输入。
8. 1366×768、1920×1080、125%缩放下主按钮与错误定位可见，Tab/回车和中文输入正常；手机现有入口与首页设置单独验收，物料本期仍隐藏。
9. 实施后执行匹配风险的模块测试、Go全test/vet、Flutter analyze/test及变更目标构建；真实UI截图与API/模拟结果分别记录。未实施前不预填“通过”。

## 用户澄清（2026-11-13）

- 品类当前只能创建、不能删除；本轮明确补齐品类删除，不额外扩展物料档案删除。
- 一个账号只设一个首页；当前终端不支持时自动回退，保留账号原首页设置。
- 随后用户明确要求“执行更新后的计划”，现已进入实施；不扩大到现场部署。

日期首次默认本月、分类父节点含全部子类、删除采用可恢复逻辑删除及混合单位分别汇总，均为本计划提出的建议默认值，不冒充已确认的产品事实。
