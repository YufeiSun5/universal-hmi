## 业务变化

开发态“登录与安全 → KP 接入”集中维护公网网页来源、后台服务地址、可选工程名、开关及账号映射。账号可搜索，内部账号/工程标识由软件处理，权限沿用监控账号。保存和应用分别反馈；直接应用新配置，旧 KP 关联会话失效，普通登录保持。旧工程 kp-bridge.json 仍为唯一配置来源，不自动修改已有来源地址、账号映射或准入策略。

结算使用数据库已返回的整站 GJ 热量，诊断状态不再清空有效数值。小时、日、月和采暖季均保留已有结果；局部缺数不清空其他有效项，有效零保留，全部无值仍为空。金额使用已有共享采暖季价格并按既有精度计算。页面与 CSV 只显示周期、站点、热量、单价、金额，开发诊断留在 API。不重算原始表底，不写现场数据库。

## 一次配置

1. 在开发态准备监控账号并分配站点、画面及业务权限，打开“登录与安全 → KP 接入”。
2. “KP 公网网页地址”填写用户浏览器实际打开 KP 的协议、域名/IP 和端口，每行一个，最多8项。它表示 KP 网站来源，与访问者所在地点及访问者 IP 无关。正式公网 KP 地址由实际部署确定，软件默认留空。
3. “KP 后台服务地址”填写监控后台核验令牌时可达的 KP 地址；同机可用回环 HTTP，跨机使用可信 HTTPS。它可以与公网网页地址不同。按实际需要填写工程名。
4. 添加账号映射，填写 KP 稳定用户 ID，搜索选择监控账号。启用接入并保存；点击“检查已保存配置与连接”检查地址和核验接口，再点击“应用配置”。检查成功仅表示接口可达并拒绝无效令牌，真实登录在 KP 画面验证。
5. 在脚本区域填写监控系统 HTTPS 地址及实际网页容器名称，复制“画面打开时”和“画面关闭时”脚本，分别放到 KP 画面的对应事件。后续在软件中维护接入配置。

当前监控系统地址为 `https://124.93.137.40:9090`，它是监控系统地址，不能代作 KP 网页地址。用户从不同地点访问时，使用已批准且由浏览器实际提交的设备证书，可沿用同一设备跨网络访问；采用 IP 白名单的客户端仍遵循原批准规则。设备证书批准、账号映射及账号权限是不同层次的校验。本批没有自动扩大 IP 范围或删除设备准入。

## 状态与排查

- “已保存配置待应用”：文件已保存，当前接入仍使用原配置。
- “公网 HTTPS 入口尚未监听”：先核对原公网入口配置及后台监听；不能把 KP 应用成功当作 HTTPS 已开放。
- “账号尚未映射”：核对 KP 稳定用户 ID，并选择有效监控账号。
- “KP 登录已失效”：重新登录 KP 后打开画面。
- 脚本加载失败或设备拒绝：核对监控 HTTPS 地址、浏览器证书与准入，并查看“拦截与访问记录”。

普通账号和公网端不提供 KP 管理接口；账号停用、权限变更、设备撤销及只读规则继续生效。已启用 MFA 的监控账号继续使用原普通登录流程，不将 KP 令牌冒充 MFA 事实。应用配置会撤销旧关联会话，KP 换号、关闭画面和令牌失效仍按现有桥接契约处理。

## 验证与交付

Go 全量 test/vet、Flutter analyze、619 项测试（2 项既有浏览器专用跳过）通过。KP 专项覆盖配置保存冲突、热应用撤销旧会话、普通用户与公网管理拒绝、两个网页来源与客户端 IP、同一设备证书跨 IP 保持及撤销后拒绝；Flutter 覆盖账号搜索、保存状态与窄屏脚本生成。

隔离 SQL Server 2017 使用数据库组 11 月 6 日的实际查询存储过程和合成采样数据，小时、日、月、采暖季四种结算逐项与 SQL 返回值对比通过。有效零、NULL、部分有效状态、金额精度和合计分别核对。实际 Chrome 日报与 CSV 只有五个业务字段；中心站 14.10416667 GJ、北站 0、张屯为空，总热量 382.60416666 GJ、总金额 9995.54 元。月与采暖季汇总 1131.35416666 GJ、29556.64 元。这些数字只属于隔离测试数据。
