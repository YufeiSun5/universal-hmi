# 内网认证与 MCP 安全边界

本页记录本轮实现合同；实际通过项以本轮验证记录为准，不替代部署验收。当前主线基点 `7d64aefe86f1ffbae7beb76761cea127d8c6f45a` 没有登录、会话或 MCP，且明确拒绝非回环监听。

## 模式与配置

- 默认本机模式保留回环服务，不自动开放内网，不自动建立账号。
- 认证模式使用操作者在本机自行准备的单用户配置，包含 `username`、bcrypt `password_hash`（cost 12–14）、显式 `allow_write`。没有内置密码、注册接口或自动生成的持久令牌。登录密码按 bcrypt 边界限制为 1–72 个 UTF-8 字节，用户名最多 128 字节。
- `--auth-file`、`--public-origin`、`--tls-cert`、`--tls-key` 配套使用；认证模式包括回环测试均要求 HTTPS。非回环地址缺少任一必要配置时拒绝启动。Unix 配置文件须仅所有者可读写；Windows ACL 由部署操作者验证。
- TLS 必须使用用户设备信任的证书。不可关闭证书校验、绕过浏览器警告，或假定反向代理的转发头可信。服务对实际 TLS 与配置的公共来源/Host 作精确检查，不因请求来自回环地址跳过登录。
- 本轮只改源码和隔离测试。没有部署内网监听、创建真实账号、安装实际证书或配置用户持久访问。

## 会话

HTTP 与 `/mcp` 共用外层认证。公开例外只有登录入口、仅返回是否启用/是否已登录的会话状态，以及不含业务能力/数据的 `/health` 状态；所有例外也必须通过 Host/Origin/TLS 检查。登录有有界速率/并发限制；会话存在进程内，随机值仅以摘要索引，8 小时绝对过期且不会随访问延长。退出即撤销当前会话，重启撤销全部会话。

浏览器使用 Secure、HttpOnly、SameSite=Strict、Path=/、无 Domain 的 `__Host-` cookie。修改请求还须带当前 `X-CSRF-Token`，包含 MCP 的 POST 请求。登录入口检查来源并限制数据格式；静态页面也受保护。过期时前端卸载工作区及其私有弹窗，返回登录界面；重新登录重建工作区。

非浏览器定制客户端可在同一 HTTPS 登录接口显式请求 `issue_token:true`，使用短期 `bearer_token`；令牌不自动保存，期限和撤销机制与浏览器会话一致。Bearer 为非环境携带凭据，不要求 cookie CSRF 头，但仍须通过 Host/Origin/TLS 检查。它不是静态 API key，不是 OAuth 授权服务器，不承诺需要 OAuth 自动发现的 MCP 客户端开箱即用。

## 读写与业务边界

账号默认只读。普通 API 的修改入口需要 `allow_write:true`；两个已知的只读 POST 预览路径 `/api/v1/rules/preview` 和 `/api/v1/import/preview` 仍可访问，但同样要求认证和 CSRF。MCP 写工具额外需要显式 `--mcp-write`，仅认证成功不代表可以写。MCP 工具保留 HTTP/业务服务已有校验、配置版本、站点作用域、命令去重、源质量、规则预览和实际执行区别。JSON-RPC POST 不能被一律视为业务修改或一律视为读操作，权限在固定工具注册表逐项判断。

支持范围/工具清单见 [MCP 覆盖](mcp-coverage.md)。声明式条件动作不是任意系统脚本，不提供 shell、任意文件路径、任意 SQL 或进程执行入口。

## 部署仍需验证

操作者需要配置受信任 TLS、可解析的内网名称和最小权限账号，确认防火墙及客户端证书信任。本轮隔离认证测试不是现场网络、真实设备或生产安全审计；不得将测试账号用于实际部署。凭据文件、证书私钥、会话 cookie 和 bearer 不应提交仓库、放入 MCP 日志或公开分享。

## 操作者准备账号（仅说明，不自动执行）

可使用系统官方 Apache `htpasswd` 工具的交互密码提示生成 cost 12 bcrypt，例如 `htpasswd -nBC 12 operator`。不要使用把明文密码放在命令参数中的 `-b`，也不要把输出、密码或配置发到聊天/日志/公开仓库。把输出冒号后的完整 hash 放入私有 JSON 的 `password_hash`，用户名放入 `username`，按需要明确设置 `allow_write`；服务只读取配置，不代替管理员设置文件权限或证书。没有该工具时可使用受信任的离线 bcrypt 工具，不应使用在线密码/hash 网站。
