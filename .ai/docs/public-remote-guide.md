# 公网访问与远程客户端配置

此方案由现场电脑运行同一套 Go 后端。公网 IP 可稍后填写：默认 `remote-access.json` 的 `enabled` 为 `false`、`origin` 为空，本机工程继续可用。这里是配置说明，实际部署验证见[验收记录](public-remote-verification.md)。

## 现场服务端

1. 在工程 `project.json` 中设置 `remoteConfig` 指向 `remote-access.json`；可从交付包的 `remote-access.example.json` 复制。配置相对路径以所在 JSON 的目录为基准。
2. 确定固定公网 IP 后，用包内 `hmi-certificate.exe --ip <公网IP> --out <新的私有证书目录>` 生成证书。保存输出的 SHA-256 指纹和到期时间。目录必须是新目录，且不能位于 `web` 内。
3. 将 `certificate`、`private_key` 填入配置。证书和私钥只保存在服务端；发给客户端的是 `server-cert.pem`，不是 `server-key.pem`。
4. 设置 `enabled: true`，填写外部实际访问的 `origin` 和现场监听的 `listen`。例如外部 TCP 443 映射现场 18443 时，`origin` 为 `https://<公网IP>`，`listen` 为 `0.0.0.0:18443`。外部使用其他端口时，在 origin 中包含该端口。
5. 明确停止并重新启动该工程后台。改配置或换证不会静默重启服务；启动器会拒绝复用配置不一致的旧进程。由现场人员配置路由器端口映射及 Windows 防火墙，只映射新增 HTTPS 监听。

首次管理员建立仍在本机入口完成。启用公网后，新增/修改密码至少7字符，既有较短密码可在本机登录后修改；远程业务需完成 MFA，权限仍由原账号角色和资源范围决定。远程入口使用同一业务API，工艺图编辑、实时订阅、查询、文件与控制仍遵守各自原有授权和成功语义。

浏览器访问 origin 时可能显示自签证书不受信任。按双方约定核对证书指纹后，由访问人员处理浏览器提示。程序不会自动导入系统信任库或关闭浏览器证书校验。

## Windows 远程客户端

使用包内 `Remote-Developer.cmd` 或 `Remote-Runtime.cmd`。两端可各自运行一个实例，重复打开唤回相应窗口。这些入口不启动本机数据库或后台。

连接设置中填写 HTTPS 地址，导入服务端的公开 PEM 证书并核对指纹。可以先保存空地址，待 IP 确定后补填。保存连接设置后，正常退出原窗口并重新打开；未保存工艺图和 GIS 草稿仍由原退出流程保护。登录页也提供“连接设置”入口。

本机工程原有快捷方式固定连接本机，不受保存的远程选择影响。退出远程客户端不停止现场后台。客户端会验证证书有效期、地址及指纹；错误主机、过期或更换后的证书都不会被静默接受。换证后需要再次导入并核对。

## 可选无人值守

现场电脑需在无人登录时持续提供服务，可按[Windows服务宿主说明](windows-service-host.md)准备独立部署目录并安装服务。此步骤默认不自动执行。服务管理工程的普通入口只连接已运行服务，不另外启动一套 PG/后台。

## 更新与回滚

保留上一版程序、工程配置、数据库备份与旧证书。换 IP 或证书时生成新的证书目录，修改配置并明确重启，再让客户端导入新公开证书。不要通过删除原工程或覆盖数据库完成升级。当前固定本机评审入口为18153；公网未启用时它保持既有本机功能。
