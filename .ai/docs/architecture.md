# 架构与分层契约（唯一母本）

## 2026-10-09 工艺画面合同

`backend/internal/process` 独立拥有画面文档校验、图片验证、文件持久化与版本冲突；`server/process.go` 转译画面和共享素材各四项 REST，MCP 经固定工具调用相同接口。Flutter `features/process` 负责纯展示几何、编辑历史、画布交互和稳定 ID 的运行快照绑定，只走统一 `PlatformApi`；`platform/process_files.dart` 适配本机/Web 文件选择。该模块不依赖 acquisition/runtime/storage，不改变采集、条件事件或物理控制。

`GET /api/v1/screens?station=` 精确选择站点，空站点表示公共画面；`GET/PUT /api/v1/screens/{id}` 读取/保存完整 schema_version=1 文档；`DELETE` 必须带当前 `revision`。创建版本为 0，成功后服务端增版；同 ID 旧版或站点变更返回 409。临时文件写入、sync、独立原子替换，成功响应才表示该画面已保存。

开发页是全局唯一入口，其目标站由页内显式选择，与站点标签的当前站独立；站点会话不保存开发页为自身页面。每站可保存多张画面，每张的元素、图片、point_id/decimals/show_unit/unit_override 独立，保存和删除一张不改变其他画面。每站当前草稿留在登录工作区内，切页/切目标站不会丢失；同站切换另一张画面前明确保存或放弃修改，进程退出前仍须显式保存。工艺画面只读查看，可从所选站/图进入共用开发页。模板导出携带图片、变量占位和显示条件结构，清除实际 point_id；引用/导入创建目标站的新 ID，同站/跨站都清空实际变量及箭头条件绑定，实例用户重新绑定，不按显示名称自动改写。自定义单位只改变显示文本，不进行工程值换算。

2026-10-09 参考图与嵌入扩展：`features/process/scene.dart` 是编辑器和查看组件共用的纯绘制层；`diagram.dart` 的公开 `ProcessDiagram` 接收文档、定义、实时快照和在线状态，在有界容器中等比缩放、居中、裁切用户放大后的视图，默认完整适配无最低缩放门槛。宿主继续拥有既有 700 ms 快照轮询，组件不新增轮询或调用写入 API。变量表以正常 UI 字体提供名称/值/单位及质量提示。`viewport.dart` 集中尺寸适配；编辑器自动适配与用户手动缩放分别保留。总览与工艺编辑页复用 `session.dart` 的站点会话、去重读取与在途草稿保护；只读组件不改变编辑器状态。开发页嵌入预览经宿主 `ValueNotifier<ProcessReadings>` 接收刷新，跨弹窗通知在宿主 build 后执行，数值更新不重置局部放大。

schema_version=1 追加可选 `label`（UTF-8 最多 256 字节），为变量表提供脱离图上位置的名称；既有无 label 文档仍有效。管道连接端口追加 `left_top/left_bottom/right_top/right_bottom`，对应参考换热器两侧四个管口；原四边中心端口仍有效。`assets/process/templates/heating-station.json` 是 1280×660 的可编辑内置蓝图，120 元素、33 个未绑定变量，实例化生成目标站新 ID/revision=0。模板不携带真实读数，不按变量名称自动绑定。四个设备 SVG 自绘、静态、保留多色外观；绑定设备的无效质量仍显式展示，外观颜色不是运行确认。

图片只接受实际可解码 PNG/JPEG，随文档以标准 base64 嵌入；不读请求指定的 URL/本机路径，不执行外来 SVG/脚本。限制：64 个画面、每画面 1000 元素/64 图片/8 MiB JSON、单张 2 MiB、边长 8192/总像素 1600 万，画布 320–8192 × 240–8192，管道 2–256 顶点。坏文件启动报错，旧文档不被无效保存替换。

共享素材由同一模块保存到 `screens/materials/<id>.json`，`GET /api/v1/process-materials` 只返回元数据；`GET/PUT/DELETE /api/v1/process-materials/{id}` 使用同一 revision 合同。工作区最多 256 个自定义素材，每项 JSON 不超过 3 MiB，图片沿用 2 MiB/实际解码尺寸限制，服务端权威返回 width/height。保留 PNG 原始字节及 alpha。Flutter 在当前登录工作区共享素材索引并有界缓存 32 张原图，各站都可拖入；放置时复制图片到独立画面文档。删除素材不级联删除画面，也不改变已有图片。

实时展示使用已有 700 ms 快照轮询，保持 unit、quality、source_time、received_time；缺失/坏质量/陈旧/离线/移站显示无效。数值支持小数位、单位和前缀；设备/管道仅用 BOOL 或数值表示开停颜色，字符串状态不推断开停。箭头动画是可配置的流向展示；绑定显示/运动条件时以宿主快照判断，外观或动画不表示设备控制成功。直角管道跟随设备移动，自由顶点仍可调整。

2026-10-10 素材端口修复：`symbol_geometry.dart` 统一素材的等比居中内容框、接触点与 0/90/180/270° 变换，`scene.dart` 绘制、`model.dart` 管道解析和编辑器端口吸附共用。`symbol_sizes.dart` 为 462 个已提交 SVG viewBox 尺寸的纯常量，由 `ci/process_symbol_geometry.py` 离线生成并以只读完整性测试核对，不依赖 UI 异步加载顺序。四个自绘设备使用审阅的绘图接触坐标；板换四管口中心为 (0/110, 32.5/125.5)，而非元素外框 20%/80%。未标注实际管口的外部素材使用等比内容框四边中点，不宣称已识别全部设备接口；矩形/图片沿用元素外框。端口名保持原稳定身份，旋转后名称不改、显示位置随图形旋转；既有带 start_node/end_node 的管道直接按新几何解析，无 JSON/后端契约迁移，自由管道不会自动猜测重绑定。

内置 FUXA 静态子集、固定来源与 MIT 通知见 [工艺画面说明](process-screens.md)。其余库、脚本及用户图片权利不由根许可证自动覆盖。画面接口共享既有 HTTP/MCP 登录、CSRF 和读写权限。保存/预览不调用 apply/write，也不代表设备动作完成。


2026-10-10 管道扩展仍用 schema_version=1 和相同 REST/MCP 用例。连接到管道的 start_port/end_port 使用 `path:<fraction>`（0–1、最多 12 位小数），表示目标管道解析后、包括圆角弧线的全路径长度比例；0/1 是端点，中间值为分支。Go 校验目标类型、范围与依赖无环；Flutter 只计算显示几何并按不可变文档缓存解析结果。目标管道移动/设备端口改变时依赖管道跟随；删除目标冻结连接位置并解除引用，撤销恢复。角度模式及步长仅为本次绘制偏好，已画顶点和 orthogonal 随文档保存；连接点优先于角度/网格。直角模式每次预览仅投影到一个水平/竖直方向，方向切换带迟滞，不因微小鼠标偏移补折线；单击确认后另起一段，只有吸附已有连接点时才补必要拐点。绘制草稿有独立最多 256 步的点击历史，未完成时 Ctrl+Z/Backspace 和工具栏撤销只回退一次点击，完成后文档整体撤销。

可选 pipe_style=flat/cylinder、pipe_rounded、pipe_elbows、pipe_bend_radius（1–128 画布 px，缺省 24）。旧文档缺省平面/直角，新绘制默认伪 3D/圆角/直径 12；弯头套环与圆角独立开关。Go 校验并持久化，Flutter pipe_geometry.dart 保留编辑顶点，计算有界圆弧（每角最多 24 条弦、半径受短边限制），渲染/命中/拼接/箭头共用缓存路径。原生矢量横截面渐变、固定左上光源、暗边/轻投影、白色暗边箭头共用于编辑与嵌入，无位图或新依赖。智能参考线与 Shift 方向约束仅为编辑偏好，6 屏幕 px 内吸附设备中心/已有管道轴线，连接点优先，其次参考线，再网格；不保存参考线，不改变运行业务。

箭头可选 arrow_mode=single/spacing/count（旧 segments 读取与保存归一为 count，数量均为整条管道）、arrow_spacing（12–2000 画布 px）、arrow_count（1–64）、arrow_animate、arrow_reverse（朝向与动画一起反向）、arrow_speed（1–500 px/s）。可选 arrow_visible_rule/arrow_motion_rule = {match:all|any, conditions:[{slot, point_id, operator, value}]}，最多 8 项，比较符为 >/< />=/<=/==/!=，有限数值，未绑定 point_id 允许模板占位。Go 权威校验结构和有界参数并持久化；Flutter 的 pipe_flow.dart 仅依据宿主快照执行纯展示比较，不参与 runtime 条件事件/工程值计算，不发控制或 apply。每个输入均须存在、属于实例站、在线且 quality=good，BOOL 按 1/0 比较；任一无效输入使该条件整体未知，显示条件未知隐藏箭头，运动条件未知停止动画。箭头总绘制预算每条最多 512；动画尊重 TickerMode 和系统减少动态效果，无新增轮询。旧文档缺省仍是静态终点单箭头。

开发页公共目标的绑定入口只显示占位，箭头条件仅编辑占位名称和比较结构。导出模板以及所有实例化都去掉实际 point_id（包括两个箭头条件的绑定），保留标签、比较结构、位置、单位、小数及图片；站点实例在开发页选择实际点位与比较条件。已有实际站点画面的普通保存保持本实例绑定，不联动模板或其他实例。

## 2026-10-02 跨架构浮点换算

工程值的合同是两次 binary64 舍入：先 `float64(raw * scale)`，再加 offset。Go 编译器允许跨语句融合乘加；ARM64 首轮CI真实暴露了大偏移抵消错误接受与十进制过零误拒绝。运行态采集、整数逆算校验、浮点逆算回环使用同一个 `engineeringValue`，显式乘积转换禁止FMA融合；不放宽可表达性、物理读回或质量判定门槛。原回归与新增对照 `math.FMA` 的向量共同保留。

## 2026-10-02 三平台安装边界

安装器仅封装经过来源/产物完整性检查的同源桌面、Go 与 Web。业务 API、认证和数据语义不变；macOS 的资源目录与用户数据目录由 Flutter 平台适配负责，个人数据不能写入应用包。Windows/Linux/macOS 安装器不创建系统服务、凭据或开放网络。实际安装/更新/卸载与包内 Web 验证见 [安装说明](installers.md)。

## 2026-10-02 虚拟点恢复时序

`runtime/engine.go` 的输入乱序拒绝只适用于异步物理/手工/模拟样本；锁内按拓扑顺序的虚拟重算不能因最早依赖源时间早于先前无效计算时刻而被丢弃。重算保留最早有效输入的源时间及质量传播，不刷新历史/新鲜度、不放松物理乱序防护。原因与红绿回归见 [虚拟点恢复](virtual-recovery-verification.md)。

## 2026-10-02 内网认证与 MCP 实施合同

新增传输边界 `server/auth*.go`、`server/mcp*.go`，仍复用已有 Go 业务用例；Flutter 统一客户端负责登录状态、CSRF 头和过期清理，不复制业务权限。认证在整个 HTTP/MCP 处理树最外层，内网启用要求显式单用户配置和实际 TLS；无回环绕过、无默认账号。MCP 固定工具注册表区分读写，写操作需账号权限与独立开关同时允许；工具输入不能任意选择请求路径或执行系统代码。配置与限制见 [内网认证](intranet-auth.md)、[MCP 覆盖](mcp-coverage.md)。本段是本轮源码合同，测试和部署结果分开记录。

## 2026-10-02 缩放与事件回归补充

本轮不新增层次：`runtime/control.go` 权威处理工程值逆算与物理原值读回，`runtime/policies.go` 权威维护存储周期/变化基线与分作用域错误，`runtime/rules.go` 提供保存及预览共用校验。验收矩阵见 [专项回归](focused-functional-tests.md)。

写入需在持久意图之前验证原值类型及正向换算回环；不可表达目标、下溢、溢出、偏移抵消不得作为成功写入。读回在原值域比较，INT/BOOL 精确匹配，FLOAT 仅容许浮点计算舍入余量，不能让大工程偏移放宽物理目标。INT 原值范围为 ±9007199254740991。非有限原始数字保留为诊断字符串 NaN/+Inf/-Inf，工程值为空且质量 bad，避免污染整个 JSON/历史查询。

重复保存同一存储策略或重复 storage_start 不重置采样时钟/变化缓存。未改变执行语义的规则（包括仅改显示名称）保留边沿、持续及冷却状态；真正改变条件/动作/启用/作用域/时序配置会重新初始化该规则。保存、预览共用规则校验；缺失/null 条件阈值拒绝，不默认零。存储、规则审计、命令审计错误按作用域保留，别的成功操作不能解除。

历史仍只有源时间和接收时间，未新增落库时刻；重复周期快照保留原采集时间。重启恢复策略但不恢复运行样本，规则禁用、不自动重连来源；新样本到达后可按原策略存储。脚本依旧是有界声明式动作序列，不执行任意系统进程。当前进程最多保留 256 条存储/审计失败详情；超限警告保留至重启，不因其他操作成功而清除。

## 状态与技术决策

2026-10-01：Go 模块化单体 + Flutter desktop/web，Linux 优先开发调试，Windows 独立构建。当前实现包含 points、acquisition、runtime、storage、analysis、server；SPT 作为通用能力审阅参考，独立 Lite 源码尚未迁入。模块边界不要求简单 CRUD 额外创建空层。

Flutter 桌面发行包会探测已有本机 Go 服务，否则启动包内 sidecar；平台文件能力经条件适配。最终包同时携带 Flutter Web，可在本机浏览器访问同一服务。后端采集/事件/存储不依赖页面；退出桌面时自有 sidecar 的实际生命周期仍需平台人工验收。默认仍只允许回环监听；本轮新增的显式认证/TLS模式见上节，部署与真实内网验收单独进行。

## 模块与职责

| 能力/边界 | 实际路径 / 后续拆分 | 公开契约 | 权威归属/允许依赖 | 禁止/验证 |
| --- | --- | --- | --- | --- |
| Flutter 展示 | app/lib/features/、main.dart | 用户操作、DTO、视图状态 | 服务器数据由 Go 权威；允许统一 API/平台适配 | 不接 PLC/MQTT/SQL；analyze、widget 与桌面/Web 流程 |
| 平台适配 | app/lib/platform/ | 窗口/文件/sidecar 接口 | 平台能力由适配器拥有 | Web 不导入无条件 dart:io；两种构建 |
| API/传输 | backend/internal/server/；transport 后续按需拆分 | HTTP DTO、稳定错误码、实时订阅 | 认证/解析/响应，调用用例 | 不做公式/换算/重试策略；handler 契约测试 |
| 点位配置 | backend/internal/points/ | 工程/站点归属、点位 CRUD/应用 | 配置持久权威；运行配置明确激活版本 | 名称不是 ID，保存不表示已采集；校验/持久恢复测试 |
| 采集与运行态 | backend/internal/acquisition/、runtime/ | NormalizedSample、点位快照/质量/时序 | 源事实经 adapter 进入内存权威 | 不从 Flutter 计算工程值；多来源契约/乱序测试 |
| 条件与虚拟计算 | backend/internal/runtime/；events 后续按需拆分 | RuleDefinition、RuleExecution、动作意图 | 纯条件/依赖规则不依赖框架；用例调动作接口 | 不识别厂商 JSON、不直写数据库/设备；边沿/质量/循环测试 |
| 物理控制 | backend/internal/runtime/；control 后续按需拆分 | WriteCommand、每步确认状态/对账 | 用例统一鉴权、版本、范围、codec 与命令身份 | 不将发布当执行、不重放未知；ACK/读回故障测试 |
| 独立存储 | backend/internal/storage/ | StoragePolicy、SampleFrame、query | 历史语义由存储模块维护；冻结配置/单位/时间 | 不依赖检测业务、不无界缓冲；断库/重启/缺口测试 |
| 分析与导出 | backend/internal/analysis/ | 筛选、分页、统计、ExportJob、ImportPreview | 查询/文件任务由用例协调，查询快照可追溯 | 不把 Excel 当业务数据库；大数据/取消/文件重读测试 |
| 基础设施 | MQTT 位于 acquisition/；SQLite 位于 storage/ | MQTT、KingIO、存储、文件接口实现 | 依赖通用公开类型；装配入口选具体实现 | 厂商字段不进领域；协议/事务测试 |
| 装配 | backend/cmd/server/ | flags/env、生命周期/health | 连接具体实现、显式配置监听/资源 | 不包含业务判定；启动/关闭/health |

点位定义以原子替换 JSON 持久化；历史、配置策略、写入意图和执行记录使用 SQLite WAL。runtime 统一编排，厂商 JSON 只在 acquisition 解析，文件操作只在 analysis。未来拆出 control/events 或支持其他数据库时维持当前权威归属。工程值只由 Go 计算。

源码依赖方向：展示→统一客户端；transport→用例；用例→纯规则/公开端口；adapter 实现端口；cmd 装配。运行时消息流不作为允许越层依赖的理由。

## 数据及状态合同

- 来源连接、工程、站点、稳定点位 ID 与显示名称分别建模。发现身份明确来源/站点/源路径；不能用动态数组下标代替稳定设备身份。
- 原值、工程值、单位、质量、源时间、接收时间和陈旧状态分别记录。坏质量或缺失不能当零/GOOD。
- 保存定义→验证→激活运行版→执行动作是不同操作；版本冲突拒绝旧配置覆盖。
- 物理动作：accepted/sent/acknowledged/readback_confirmed/failed/unknown；未知提供对账，不自动重写 PLC。
- 历史帧冻结相关单位、换算、成员及配置版本，后续修改不重算旧历史。
- 导出冻结查询条件和读取边界；重复分页、取消、超大数据和失败文件有明确结果。
- 本地默认为回环监听；远程访问先建立认证/权限及安全部署合同。开发 CORS 必须显式白名单，不能代替鉴权。

## 核心流程 A：用户添加点位到历史导出

入口为 desktop/web 用户，通过统一客户端。
1. 添加来源与点位/导入列映射，前后端校验稳定身份、站点、类型、单位、可写目标及换算。
2. 保存配置成功产生持久配置版；用户选择应用后发布运行版，失败保留上一有效版。
3. adapter 接收样本，保留源时间/质量，经换算写运行态；UI 展示实时/离线/缺失。
4. 独立存储策略按周期/变化/条件创建采样帧，有界入队；仅持久提交后算落库成功。
5. 用户按工程/站点/点位、时间、数值、质量筛选历史，读取分页统计/降采样图表。
6. 导出任务冻结条件/语义并异步处理；完成后文件可下载/保存，Excel 重读核对源行及类型。

失败/恢复：配置冲突拒绝、协议错误可见、断线值陈旧、存储缺口可查、任务取消区分已提交结果。验收包含真实文件重读以及单独的现场协议测试。

## 核心流程 B：后台条件事件与受控动作

入口为后台规范化样本/定时扫描，无 UI 会话依赖。
1. 规则引用稳定点位 ID，批次/新鲜度要求显式；缺失/BAD/陈旧输入产生 unknown。
2. 纯规则检查 AND/OR、持续时间、防抖、成立/恢复边沿及冷却，生成唯一执行身份。
3. 多步动作调用 control/storage 用例。下设重新校验当前权限、目标、范围和编码版本；快照绑定事件输入/运行版本。
4. 设备发送、ACK 和新鲜读回分开；存储队列接受与数据库提交分开。
5. 每步记录结果及部分成功，不承诺跨设备与数据库原子事务。
6. 重启恢复未决执行，查询/对账已发生的动作；结果未知不盲目重放；安全存储可按身份去重。

验收：同时满足、条件抖动、持续成立、恢复、重复样本、乱序、坏质量、脚本超时、队列满、写入未知、部分成功及进程中断。

## 技术未知与迁移约束

SPT 正式版路径中存在检测依赖，不否定用户确认的独立存储能力。需定位对应 Lite/其他实现，记录来源提交、许可证、依赖和移除清单。不复制 SPT 客户配置、测试数据及真实凭据。真实 Kepserver/KingIO 格式和总负载未确认，现有样例不是通用兼容证据。

### 2026-10-02 后端重建合同

本轮从可访问公共基线重新实现，不是遗失工作树的逐字恢复。点位批量创建 POST /api/v1/points/batch 一次校验、一次原子保存，最多 20000 定义。运行层激活后使用稳定 point_id 与 source_id/topic/source_path 索引；一个来源可承载多站，多个来源中的相同路径保持隔离。容量目标为 5 来源、30 站、每站 500 点，总计 15000 点；模拟/本地 MQTT 验证与现场容量认证分开报告。

GET/PUT /api/v1/storage?station= 与 POST /api/v1/snapshot?station= 固定请求的站点作用域；空站点为独立全局策略。站点策略持久化、点位引用必须属于该站；配置移动点位后旧站规则产生未知，旧站策略不会捕获新站值。规则可带 station；条件与写动作都在运行时重新检查所属站，存储动作使用规则自身作用域，重启仍禁用规则。历史样本冻结 station，历史目录按 point_id+station 保留迁移前后的记录；目录默认/上限 20000，返回 limit/truncated。导出 Job.station 与完整筛选边界在任务创建时冻结，后续界面切站不改变排队任务。

物理写入需通过 GET /api/v1/points/{id}/write-capability 返回的数值类型、工程值范围与原因校验；字符串物理写不支持。KingIO 要求 writable=true 且 rw_mode 为 W/RW；write_source_id/write_path 可独立指定，缺失时回退到读取来源/路径。来源保存 client_id、writer、ack_timeout_ms，凭据不属于来源或状态 JSON。测试用临时认证只经 adapter 连接参数注入，不加载客户凭据。

POST /api/v1/write 要求显式 value（缺失/null 拒绝），持久化意图后返回 accepted；4 个工作协程、最多 32 个排队任务、最多 64 个未完成命令，发布前复核活动版本与连接。ACK 等待不持有运行全局锁，不阻塞采集消费。命令字段 publish_state、ack_state、readback_state 分别记录发布、设备响应与读回，GET /api/v1/commands/{id} 可对账。同 ID 同载荷只返回旧结果，不重发；不同载荷拒绝。未发送的排队命令停机后为 not_sent；已经开始发布但终态不明的命令重启后为 unknown，不自动重放。只有相关 Qid、ProcessStep=100、Result=OK（大小写不敏感）算设备成功 ACK；物理读回另须读取目标、活动版本、类型、质量、目标值都匹配，且不是 retained、不是乱序、时间晚于本次发布。ACK 已到但没有新鲜读回仍为 acknowledged/unconfirmed，不能冒充 readback_confirmed。
