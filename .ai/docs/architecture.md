# 架构与分层契约（唯一母本）

## GIS有序分区与绑定搜索（2026-10-30）

GISStation新增可选`zones:[{id,name,bindings}]`，数组顺序即浮窗顺序；原`bindings`保持为站公共数据，无分区旧文档原样读写。每站最多16个分区，稳定ID在站内唯一，名称最多256字节；每组沿用五种已有指标槽。分区是展示配置，不是资源树业务站点，不迁移或复制变量，不启动采集/存储。保存沿用画面revision及公开screens接口；公共和分区引用都经过授权目录检查。客户端读取分别裁剪无权变量，Flutter按全部组引用去重订阅，地图只渲染已授权工程值与质量。删除变量递归检查分区引用；显式旧工程重建清理分区绑定而保留分区名、顺序及布局，普通升级不调用重建。

开发态在GIS站点编辑中添加、改名、删除及上下排序分区，先改草稿，保存画面后持久化；取消不改原配置。浮窗公共数据在前，分区按数组顺序两列展示，窄屏单列和内部滚动。工艺节点绑定、公共实例绑定及GIS绑定复用`shared/variable_search.dart`的多通配OR语义。变量矩阵按静态名称/站点/单位测量完整换行高度，继续虚拟化实时单元格；长单位使用底部对齐避免基线增加隐藏高度。本轮实际证据见[GIS分区验收](gis-zones-v19.md)。

## 桌面窗口空间预算（2026-10-30）

窗口尺寸变化只影响视图，不修改工程状态、筛选和选择。Flutter开发壳在1100逻辑像素以下紧凑显示命令栏，在1000以下将资源树改为显式可打开的抽屉；详情区域按资源树、活动栏和自身宽度扣除后的主区预算决定显示。变量设置及监视工具栏允许换行，列表保持独立滚动，不通过缩小字体或裁掉主要操作维持单行。Windows runner通过WM_GETMINMAXINFO给出900×600逻辑像素的最小外框，随显示器DPI缩放，并以工作区尺寸为上限；Web仍允许更小视口并由布局适配。最终实际验收及多DPI边界见本批验证，规则不代表所有旧页面均已完成视觉复验。

## 变量通配搜索与批量选择（2026-10-30）

Flutter `shared/variable_search.dart` 为变量列表、曲线/关注选择及删除候选的统一匹配器，与Go扫描`runtime.discoveryMatcher`语义对齐：普通文字忽略大小写按子串查找，含`*`/`?`按单个完整字段匹配；`?`消耗一个Unicode字符，逗号/中文逗号/换行分隔OR条件。搜索字段为名称、站点、单位、稳定ID、来源ID、源路径和主题。扫描仍调用后端公开发现接口，不在前端复制目录权限或类型判定。

变量列表批选以稳定ID保存，与最多6条的曲线和关注集分开。表格与虚拟矩阵共用选择，逐项勾选、Ctrl切换、Shift连续、全选当前筛选及清空；改变搜索保留列表选择，切换站点清空，目录刷新剔除已删除或已移出当前站的ID。加入曲线或选择窗口筛选全选按合并后数量校验，超6明确报错且原选择不变。批量删除只预填有效ID，仍必须经过后端预览/修订/依赖检查和显式提交。批选本身不改归属、定义、采集、绑定或历史，不Apply、不下设。扫描沿用修订校验的跨页全选及筛选变化重置选择，并明确显示此差异。


## 设备台账导航与图片显示（2026-10-30）

equipment模块维护独立`equipment_navigation`配置，通过`GET/PUT /api/v1/equipment-navigation`读写`{revision,nodes}`。节点由稳定id、label、可选station/site和children组成；分组不带业务归属，叶引用站区及可选小站筛选。菜单只负责展示与筛选，不迁移设备、不改站点或变量身份、不增加站点删除依赖。未配置时读出空树，客户端沿用默认站区目录；启动或升级不写默认菜单。保存要求有效账号具有全站开发权限，验证稳定ID唯一、最多4层256项、文本长度、组/叶结构及站区存在，revision冲突拒绝。读取按现存站和账号授权过滤，移除空组，不改原配置或revision。

设备档案新增可选`photo_fit`：空值兼容`contain`，支持`contain`完整显示、`cover`等比裁切铺满、`fill`拉伸填满。开发端保存档案时显式持久化；运行端临时选择仅影响当前查看，不写工程。照片身份、原始字节及原照片接口保持；Flutter按API实例/设备ID/照片ID管理请求与解码缓存，同一照片重建复用字节，身份切换退役旧请求并清除旧显示，失败提供重试。照片与状态轮询互不触发重复请求。

列表和档案详情使用一致的设备修订快照订阅`equipment/status`，不放宽后端结果与设备revision匹配；缺失、坏质量、陈旧及离线语义保持。设备状态仍由后端计算，前端不推断物理运行状态。原菜单、设备、照片、信号绑定、来源、变量和历史不由本次升级重写；实际验证状态以唯一看板和本批证据为准。

## 服务器站点重建与配置删除（2026-10-29，v11 已交付）

v11安装器的v10固定标记清理选项面向用户已授权的旧工程重建：安装器明确展示当前用户/规范化工程路径与精确范围，可取消；静默安装不默认清理。启动器取得工程锁并确认后台/私有PG已停止后，在工程外的私有备份目录完整冷备工程，逐文件核验来源前后与备份摘要，备份失败不执行清理。临时启动已核实的私有PG，调用独立离线重建工具；工具不创建runtime Engine、不连接MQTT、不执行设备操作。

v12部署修正版针对Windows内置管理员的目录owner语义：除当前SID为owner外，仅在已启用管理员角色、owner为Administrators组、受保护DACL、当前SID有覆盖目录与子项的显式FullControl、无Deny及无非受信主体写权限时接受既有工程。源工程ACL不改；仅新创建的私有维护目录可规范化owner，已有目录必须先授权核验。失败诊断以CreateNew写到持久安装日志旁，包含阶段与固定安全错误码，不写原始异常Message或配置凭据；早期失败不依赖工程维护目录已经创建。验证与现场限制见[管理员维护修复](windows-maintenance-admin-v12.md)。

离线工具通过storage公开事务适配器，在单PG事务内按计划移除旧points定义、非GIS工艺图、显式站点目录及失效规则/存储配置；GIS只解除已删变量与工艺目标关联，保留布局与素材；设备资产及图片保留，仅解除旧点关联。MQTT sources原配置不改、身份/授权/历史不删除，公网及密钥文件不改。固定`process-rebuild-v10`标记与清理同事务提交，失败回滚；工具状态可用于崩溃后恢复完成凭据，重复启动不再清理。pending/失败未解状态阻止普通后台启动。仅重置工程采用显式目录模式，历史查询继续保留旧站数据，但不能因历史记录复活已清空的站点目录。

变量批量删除通过独立公开preview/commit接口接受id及revision，预览列出工艺/GIS、派生点、设备、规则与存储引用；任意无权、缺失、修订冲突或未处理引用均整批阻挡，commit重算token后一次原子持久化，不由Flutter循环逐个删，不自动应用运行配置。站点删除亦检查当前点/画面/设备/规则等引用，只删除可删除目录项并记录历史投影抑制；保留历史数据，明确重新创建同名站可恢复目录。具体实现状态与验收以唯一看板为准。

本机与公网处理器共享进程级配置写入保护，所有 API 写请求串行进入，避免删除引用检查后被另一请求插入引用；普通单点删除也走相同引用检查。新增规则和存储配置校验已保存变量目录，不使用尚未应用的旧运行时目录判断存在性。删除站名写入抑制记录，旧编辑窗口不能借保存点、画面等操作复活该站；必须显式重新建站。首次 MQTT 扫描填写的新归档组仍按既有流程支持。该写入保护与各业务自己的存储事务分别承担并发和原子提交职责。

## 工艺导入批量引用已有变量（2026-10-29，v11 已交付）

迁移preview/commit沿用公开接口，新增显式`variable_targets[key].mode=match_existing`。由用户选择批量匹配及来源映射后，后端仅在指定真实MQTT来源内按完整source_path精确查找；包topic非空时额外精确限定主题，空时查所有实际主题。唯一候选且兼容才解析为现有ID，不按显示名称推测、不新建变量、不改变现有归属/采集配置/历史。旧auto匹配语义保持。多候选、类型或显式单位/倍率/偏移冲突均未解决；包内未知单位或未提供的倍率/偏移不能当作覆盖指令，预览展示实际值及差异。所有候选按授权过滤，存在不可访问候选不能假称唯一，也不能泄漏隐藏元数据或数量。

预览项提供可见候选定义、revision、兼容性及冲突/差异，成功引用展示实际目标；commit重算，原preview_token覆盖请求和解析结果，候选变化需重新预览。Flutter批量操作仅设置显式模式，仍需用户预览确认保存；导入文件create/update预填需正确恢复变量定义选项，开关不能静默删除用户已选映射。保存引用与启用采集分开。实现/验收状态见唯一看板，未作为现场验收结论。

## 客户端四业务与外部历史（2026-10-29）

客户端业务导航仅GIS、工艺画面、设备台账、历史，历史统一复用externaldata的日报/明细/趋势目录和查询接口，不再进入本系统history报表/曲线。Flutter按实际客户端模式分流，包括有develop权限但明确打开runtime的账号；旧客户端页选择不得绕回内部工具。无view的开发入口及KP既有入口语义保持，新增历史直达链接按客户端外部历史处理。

客户端初始化和刷新不加载内部history/catalog、jobs及storage策略；points/runtime/stations继续按GIS、工艺、台账所需使用。内部历史、报表曲线、文件任务、存储与变量工具留在开发工作台，原Go用例、数据与采集行为保持。本轮不因页面移动改变授权、删除数据或停止存储。

客户端历史只走`/api/v1/external/`公开契约；保留独立external_screen_ids授权、原有时间/分页/质量语义及明确空态/错误。无授权、未配置、外部连接失败均不得回退本机历史。工程师在开发端配置外部来源和画面，客户端不提供来源管理；账号安全、连接与退出为必要外壳操作，不属于额外业务模块。MonitorHeader造型、标题时钟和GIS独立视觉沿用既有设计。

## 可配置公网与客户端远程连接（2026-10-29）

产品选择为固定公网IP、自签证书、路由映射；IP稍后填写。同一Go进程在既有本机身份入口之外增加可选正式TLS监听，共用一个业务运行时、存储与identity服务。`project.json.remoteConfig` 指向 schema=1 的JSON（enabled、origin、listen、certificate、private_key）；默认禁用且origin为空。启用需要完整HTTPS IP origin、监听地址、证书/私钥及有效IP SAN，保留真实TLS/Host/Origin/MFA和既有授权。启用校验失败不降级；证书工具生成非CA叶证书，不自动信任系统或覆盖现有私钥，私钥禁止放入Web目录。启动器通过本机部署端点核对配置与证书摘要，配置或换证要求明确重启，不静默复用旧HTTP进程。公网启用时共享密码创建/更新政策为7字符，旧短密码仅可本机登录改密，远端拒绝；本机会话跨到远端仍须完成MFA。

桌面连接设置持久化远程地址、绑定origin及公开PEM证书，允许先保存空地址草稿。普通工程启动器明确传递 `--local-only`；独立远程双端入口传递 `--remote-only`，不启动本机PG/sidecar且不拥有远程后台。裸EXE兼容已保存选择。连接设置单独窗口仅保存，退出并重新打开后生效，失败页可保存修正后重启；已有工程草稿仍走原退出保护。远程实例身份优先使用规范化endpoint并区分两端。专用TLS上下文校验主机、有效期和逐连接叶证书SHA256，限定origin且禁重定向，覆盖API/SSE/文件。GIS使用随机路径的只读回环静态代理、同一TLS信任及CSP；WebView2原生NavigationStarting限制地图页面导航并禁弹窗。Web仍由浏览器处理自签提示。公网全部能力由原后端授权决定，不因远程入口变成全权或只读。实际公网IP、路由和防火墙未配置；隔离测试不能代替现场公网验收。

可选Windows无人值守宿主使用SCM启动专用PG与同一后端，普通入口发现service-host.json后只连接服务，禁止抢启另一后台。服务不接管已有PG，只停止本次拥有的实例；独立部署目录、ACL、安装/移除和未验范围见[服务宿主](windows-service-host.md)。不自动安装系统服务。

## Windows 桌面生命周期（2026-10-29）

同一 Windows 用户/登录会话、同一工程数据目录、同一端角色只持有一个桌面实例；developer独立于runtime（gis/process归runtime）。packaging/Start-Project.ps1及windows-lazy/Start-HMI.ps1向桌面传递HMI_PROJECT_DIR与既有HMI_API_BASE_URL。锁身份不依赖程序版本路径、窗口标题或可变端口；路径规范化。直接启动的身份回退沿用HMI_DATA_DIR/平台默认目录，编译指定endpoint参与远程实例身份。

Runner可先创建隐藏引擎，通过Dart/native初始化握手获得endpoint。连接引导阶段通过deferFirstFrame阻止窗口首帧显示，实例确认必须早于健康探测、后台启动及首帧显示。第二实例只唤回对应窗口并正常退出；并发初始化、原进程崩溃和锁释放需有界处理。窗口锁不代替launcher已有的后端启动锁。

关闭/Alt+F4默认收起托盘，普通最小化保留任务栏，系统菜单提供主动收起；托盘区分开发端/用户端并提供打开和退出。只有图标注册成功才隐藏，Explorer重启重新注册，失败恢复可见窗口。退出通过公开平台退出请求，经Dart注册guard检查并提交聚焦输入、所有工艺/GIS草稿及保存中的操作；取消或保存失败保留窗口。允许退出后继续既有owned/reused后端与渲染排空流程，不硬杀伪造成功。正式launcher的共享后台不归客户端拥有，退出一端不影响另一端或采集/存储。

裸EXE原自有sidecar兼容路径不扩展为多进程服务管理：无共享/编译endpoint时增加同工程跨角色启动保护，避免第二裸进程借用第一端拥有的服务后被退出误停。需要双端并存时使用正式工程双入口，不混用裸EXE。Web为平台no-op，Linux现有退出语义保持。原生销毁先注销channel并清空成员防止重入，显式Destroy早于CoUninitialize。实际通过项和未验范围见[独立验证](desktop-lifecycle-verification.md)。


## 工艺模板、独立复制与背景（2026-10-29）

内置四种供热布局按结构命名（分支计量三泵、单路计量三泵、单路计量单泵、双表串联单泵），源模板 station 为空、变量与箭头条件均不绑定，不携带真实站名。PNG设备仍使用现有素材目录；管道、文字、读数和设备为可编辑节点。

开发资源目录与编辑器提供“复制工艺图”：使用现有 GET/PUT screens 公开接口创建新身份的独立文档，保留完整布局、内嵌资源及背景，解除 template_id/template_revision，清空数值与箭头条件中的 point_id，不按名称重绑。目录复制已保存版本，编辑器复制当前草稿快照；源文档与未保存标签不被覆盖。保存失败保留表单；响应丢失后只读核对同 ID 的完整内容，只有确认一致才视为成功。此入口与“公共画面引用”是不同工作流，后者继续同步公共布局。

### 2026-10-27 已实现合同

`--identity` 启用 `identity` 用户/会话/站点注册与审计，`authorization.Actor/Grants` 为HTTP、MCP及业务用例的共同授权数据。身份数据库位于工程数据目录 `security/`，不重写既有点位和历史。站点注册以既有不可变station键映射随机稳定ID；发现新站不继承同名以外站点的旧授权，当前没有站点改名API或历史归属迁移功能。用户由管理员显式选择ID授权。

角色可组合；`engineer + all_stations` 才能开发/发布，`admin + all_stations` 才能管理用户，管理员本身不含工程师能力。局部工程师当前拒绝开发，不以全量替换实现局部发布。`control`、`grant_control`、`export` 分开，初始owner为admin/engineer/auditor，允许授予控制但自身control为false。权限修改受可授予能力、版本冲突、最后管理员及自修改约束。

Argon2id密码、8小时绝对/30分钟空闲会话、摘要token、Cookie/CSRF、登录限流、改密/禁用/改授权撤销已实现；自动runtime/SSE/job轮询不续空闲。TOTP、单次恢复码、管理员重置及密钥加密/目录权限已实现。远程实际TLS模式强制MFA，未完成绑定前只允许会话和MFA引导。显式 `--identity-local-setup` 仅回环HTTP，拒绝代理头，用于本机首次建号和评审；不会创建默认密码。桌面自启携带身份参数，拒绝复用旧匿名健康服务。

按授权裁剪点位/公式元数据、实时/SSE、历史/统计、画面绑定/跳转、菜单；额外共享画面包含静态文字，不附带外站数据。文件任务绑定owner/授权版本，排队执行和下载重查；规则绑定显式执行身份，控制在发送前再查，撤权后不伪造已发送命令的撤回。安全变更和受控操作留本机审计，写操作前审计失败拒绝；审计不是外部不可篡改记录。

正式KP可组合统一身份，可信verifier提供 `mfa_verified` 和 `authenticated_at`，以配置中的稳定user_id关联已建账号，KP实例与统一会话双重校验；不能与用户名试验模式组合。Flutter提供独立账号安全/权限管理，非工程师只进入用户监控端。首版操作员不额外开放开发或控制动作，设备下设仍需control明确授权。

本批验证及部署见 [security-verification.md](security-verification.md)。以下设计中尚未实现的Passkey/OIDC、端类型策略、局部发布、双人批准、外部审计/备份及实际网络运维继续作为目标；不可据本批测试认定公网已可开放。

### 身份、角色与范围

授权依据为「稳定用户身份 + 明确动作 + 工程/站点/资源范围 + 会话与安全策略」，默认拒绝；IP、显示名称、菜单位置及前端当前站点均不产生权限。每次请求和实际执行都验证权限，规则参考 [OWASP授权建议](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

预置角色只是可审阅的权限集合，不把单个AllowWrite布尔值扩展成更多前端判断：

用户在2026-10-27最终确认：保留工程师角色，工程师可以开发，其他用户不能开发，并已授权实施。本节据此修订，取代上一轮“任何用户都无开发权”的方案。工程师必须显式授权，管理员不自动兼任工程师；角色可组合，但授权管理不能隐式自提权。以下为完整目标，当前具体边界以上述已实现合同为准。

| 预置角色 | 默认能力（均受授权范围限制） | 需要另行授予 |
| --- | --- | --- |
| 查看员 | 使用Web/用户端查看获准画面、实时值与历史 | 导出及其他已发布业务动作 |
| 操作员 | 使用Web/用户端执行获准的日常业务动作 | 已发布业务功能中的设备下设、用户管理；开发能力不可授予 |
| 工程师 | 获准范围内的画面、点位、菜单、公式、规则及来源开发配置 | 设备下设、用户管理；全局发布须工程级开发授权 |
| 安全管理员 | 用户、角色、范围、会话及安全策略管理 | 设备下设；授权变更须留审计且不可越出自身可授予范围 |
| 审计员 | 获准范围内的审计与执行记录 | 批量导出；不含业务修改、开发或删除审计 |

用户可授予动作限于已发布业务功能，如 `screen.read`、`point.read`、`history.read/export`、`control.write`、`user.manage`、`role.grant`、`audit.read`，并受工程/站点/资源范围限制。Web及用户端访问可分别配置，但端类型不能仅靠客户端自报、User-Agent或自定义请求头认定，须在服务端认证/会话策略中约束；两种入口共用业务授权。

`screen.edit`、`navigation.manage`、`point.edit/reference`、公式编辑、`runtime.activate`、`source.manage/connect`、`rule.edit/enable`、`storage.manage`及工程导入/开发素材编辑属于工程师开发能力，普通用户与仅有管理员角色的身份不可调用。旧AllowWrite、KP operator、客户端参数和MCP写开关不能隐式取得工程师能力。用户的数据分析文件导入/导出与工程配置导入分开。后端检查明确能力与资源；授权管理要求近期认证和审计，角色修改不能超出自身可授予范围或无记录地自提权。

非工程师界面不提供开发工作台、编辑器及开发菜单，不能用 `?view=development` 等直链进入；后端独立检查开发能力，工程师有权限时才可操作，不能仅隐藏前端入口。共用业务用例保持同一权限契约。MCP开发写工具除独立写开关外也要求工程师能力，普通用户凭据不能调用。用户管理界面独立于开发工作台，工程师开发不自动获得账号管理或设备控制权限。

第一阶段仍为单工程内多用户、多站授权，不承诺多租户隔离；多工程继续归PROJECT-01。工程、用户及站点授权需要稳定ID。当前多个结构以station字符串表达站点，正式站点授权前先定义稳定station_id注册与兼容迁移，保留旧名称及历史归属快照；重命名或点位移站不能隐式改授历史访问权，不能以字符串重写全部历史完成迁移。

用户管理包括创建/邀请、启用/禁用、修改角色与范围、重置凭据、查看和撤销会话；不提供开放注册或默认密码。首管理员经本机一次性引导或受控安装流程建立，恢复流程留审计，避免删掉最后一个有效管理员后无恢复入口。新密码存储优先Argon2id，既有bcrypt通过版本化策略逐步迁移；不得记录明文或截断密码。支持长口令、泄露/常见口令拦截、账号与来源组合限流、统一失败提示和有限退避，避免攻击者靠反复失败永久锁死账号。账号禁用、凭据重置和降权撤销旧权限/会话，长连接同步失效。参考 [OWASP认证建议](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

浏览器优先短期服务端会话与HttpOnly Cookie，配置空闲与绝对期限、会话轮换、当前/全部终端退出。公网访问要求MFA；特权用户及远程控制优先抗钓鱼Passkey/安全密钥，离线内网可选本地TOTP及受控恢复。企业OIDC与KP只负责可信身份接入，均映射稳定user_id及同一授权服务；MFA强度要有可信证明，不能因走另一登录入口绕过。桌面与MCP使用独立有期限凭据及系统安全存储，不复用长期管理员口令。

### 数据与画面授权边界

1. 列表、详情、搜索、数量、统计、实时/SSE、历史、文件预览/下载及MCP全部采用后端授权范围；客户端station参数只能进一步缩小范围。工程配置批量保存及全局apply要求工程师能力，并验证全部受影响资源和版本；仅有局部站点权限不能全量替换其他站配置，全局操作须工程级开发授权。
2. 全工程实时快照可以内部共享，输出必须先按权限裁剪；不得把仅按时间缓存的全量JSON直接交给局部用户。缓存键包含范围与权限版本，撤权关闭/更新SSE并清理前端旧数据，重新连接不能取回旧授权数据。
3. 菜单分组只组织展示；服务端返回用户可访问的叶子及必要祖先，点击父组打开首张可访问画面。GIS跳转重新验证目标画面访问权；禁止只在UI隐藏未授权入口而保留可读直链。
4. 公共画面与跨站GIS不自动授予引用变量的读取权限。目标画面、引用值和配置元数据分别判权；无权限不输出值、绑定细节或敏感站名。跨站共享画面的可见静态内容也须明确授权/审阅，不能声称仅遮数值就隐藏了画面中人工文字。
5. 虚拟点的归属与输入引用继续分离：可查看已授权派生结果不代表可读取上游原值或公式；公式开发只对工程师开放，跨站依赖须验证全部输入的引用权限。派生结果的共享须显式授权，不把计算作为隐式跨站数据通道。
6. 上传、预览、异步导出及下载绑定稳定创建者、工程、数据范围和权限版本。排队、执行、下载均复核当前权限；撤权后停止未开始的任务并拒绝文件下载。历史授权按保存时归属处理；猜测job_id或point_id不能获得其他人的文件/数据。共享任务必须显式授权。

### 设备动作和后台执行

保存开发草稿、发布运行及启用规则要求相应工程师能力与范围。设备下设为单独的control.write能力，工程师或管理员均不自动获得；普通操作员只能操作已发布的既定目标，不能修改点位映射、公式或规则。直接下设及既有后台规则动作都经后端受控写入服务，检查目标、当前授权、允许范围、配置版本与命令ID；需要时执行近期认证/二次确认，关键现场动作可配置双人批准。

后台规则使用显式、受限的执行身份及授权范围，记录发布人、版本与执行主体，不能在用户退出后继续借用其无限权限。撤销执行身份阻止新动作；撤权发生在排队期间须在实际发送前再次检查。已发送动作保留未知/应答/读回状态并对账，不以退出或撤权伪造撤回成功。共享采集和存储不因普通查看用户退出而停止。

### 公网、内网与运维

- 本机开发模式仅回环且明确标识无登录，不得被反向代理转成公网匿名入口。内网服务同样启用身份、TLS和权限，不因来源是内网IP或回环代理而绕过。保留现有联网启动拒绝规则，禁止静默降级。
- 推荐公网入口只暴露HTTPS 443，经受控入口/反向代理进入已认证服务；OT设备、MQTT broker、数据库与管理端口不直接暴露公网。公共展示如确有需求，另建显式只读、最小数据投影，不能等同完整HMI匿名访问。远程维护优先VPN/零信任访问入口与MFA，控制链路按区隔离。
- 目前Go必须实际承载TLS，不能直接假设代理终止TLS后转HTTP可用。第一步可采用TLS透传或代理到Go的受信HTTPS；若后续支持TLS终止，必须配置可信代理地址/跳数、覆盖外来Forwarded头、精确公共Host/Origin及仅代理可达的后端监听，并独立测试。禁止通过篡改Host把联网访问伪装成本机模式。
- 限制每账号/来源/全局登录、API、SSE及文件任务资源；覆盖请求体/解压体积、行数、CPU、执行时间、队列和磁盘容量。输入验证、参数化数据库访问、路径与上传类型校验、CSV公式安全、CSP及安全响应头需针对Flutter/WASM/Cesium/KP嵌入实际验证，不能直接放宽到任意来源。
- 来源连接由获准工程师配置，身份verifier等部署目标由受控部署流程管理，均受网络允许范围约束，不因用户管理员角色而开放；正常工业网段作为明确允许项，不以“禁止一切私网”破坏采集。MQTT使用独立最小权限身份、TLS与topic ACL，密钥只在后端私密存储，前端/API/日志不回显。
- 审计记录主体/会话、动作、资源范围、授权决定、配置前后版本、请求/命令关联ID、来源和结果；不记录密码、token或全部敏感报文。特权动作审计落盘失败应拒绝新操作；普通读取的日志故障不阻断既有设备安全运行。限制审计读取/删除，集中留存及完整性保护，不将同机日志称作不可篡改。
- 使用低权限服务账号、私钥/数据目录ACL、数据与Web静态根目录分离、受控更新和依赖漏洞检查/SBOM；备份加密并验证恢复、证书到期告警、磁盘/异常登录监控。防护和限流不能阻塞既有采集/保护回路；安全与可用性一起验收。

### 模块与实施顺序

保留Go模块化单体。计划新增 `backend/internal/identity`（用户/凭据/会话）、`authorization`（动作/范围/策略版本）、`audit`（安全事件）；名称是计划路径，尚未创建。server只解析认证凭据、建立Actor并调用公开用例；各业务用例通过授权公开接口判权和查询约束，避免绕过HTTP后失去保护。存储/analysis/runtime/process采用受约束公开接口，Flutter仅据能力控制界面；现有KP桥通过身份适配器接入，不复制用户库。用户/角色管理UI计划置于 `app/lib/features` 的全局管理入口。

实施顺序：① 工程师与普通用户的开发边界、稳定站点身份与兼容迁移、用户/角色/范围/会话权威及审计；② 所有业务入口和数据投影接入，补普通角色拒绝开发/工程师正向操作、历史/导出/SSE/MCP/规则执行越权回归，形成独立用户管理界面；③ MFA/可信身份接入、网络边界与运维配置，做真实内网/公网验收。前两阶段没有完成覆盖前，不宣称系统可以安全公网部署。

验收必须包含非工程师角色（含单独管理员）的开发路由/开发接口/MCP开发工具拒绝、工程师正向开发、伪造端类型、旧operator/AllowWrite及自定义角色无法隐式获得开发权，以及同名跨站、未知ID、直链与批量越权、权限撤销后SSE/缓存/导出、跨站画面/虚拟引用、角色自提权、不同登录入口一致性、CSRF/Host/代理伪造、账号禁用/重启/恢复、限流和资源耗尽、规则绕过控制权限的失败路径。设备动作使用模拟端验证，不以安全测试触发现场控制；公网开放另按实际拓扑验收。工作状态只在AI_BOARD的SECURITY-01维护。

## 2026-10-02 内网认证与 MCP 实施合同（现有实现）

新增传输边界 `server/auth*.go`、`server/mcp*.go`，仍复用已有 Go 业务用例；Flutter 统一客户端负责登录状态、CSRF 头和过期清理，不复制业务权限。认证在整个 HTTP/MCP 处理树最外层，内网启用要求显式单用户配置和实际 TLS；无回环绕过、无默认账号。MCP 固定工具注册表区分读写，写操作需账号权限与独立开关同时允许；工具输入不能任意选择请求路径或执行系统代码。配置与限制见 [内网认证](intranet-auth.md)、[MCP 覆盖](mcp-coverage.md)。本段是本轮源码合同，测试和部署结果分开记录。

## 2026-10-02 缩放与事件回归补充

本轮不新增层次：`runtime/control.go` 权威处理工程值逆算与物理原值读回，`runtime/policies.go` 权威维护存储周期/变化基线与分作用域错误，`runtime/rules.go` 提供保存及预览共用校验。验收矩阵见 [专项回归](focused-functional-tests.md)。

写入需在持久意图之前验证原值类型及正向换算回环；不可表达目标、下溢、溢出、偏移抵消不得作为成功写入。读回在原值域比较，INT/BOOL 精确匹配，FLOAT 仅容许浮点计算舍入余量，不能让大工程偏移放宽物理目标。INT 原值范围为 ±9007199254740991。非有限原始数字保留为诊断字符串 NaN/+Inf/-Inf，工程值为空且质量 bad，避免污染整个 JSON/历史查询。

重复保存同一存储策略或重复 storage_start 不重置采样时钟/变化缓存。未改变执行语义的规则（包括仅改显示名称）保留边沿、持续及冷却状态；真正改变条件/动作/启用/作用域/时序配置会重新初始化该规则。保存、预览共用规则校验；缺失/null 条件阈值拒绝，不默认零。存储、规则审计、命令审计错误按作用域保留，别的成功操作不能解除。

历史仍只有源时间和接收时间，未新增落库时刻；重复周期快照保留原采集时间。重启恢复策略但不恢复运行样本，规则禁用、不自动重连来源；新样本到达后可按原策略存储。脚本依旧是有界声明式动作序列，不执行任意系统进程。当前进程最多保留 256 条存储/审计失败详情；超限警告保留至重启，不因其他操作成功而清除。

## 变量归属、派生与存储

本节是已确定变量语义的技术合同；产品目标仍以 [agent.md](../../agent.md) 为准。实际验证和代码索引见 [变量与存储核验](variable-semantics-verification.md)。

- **范围与身份**：当前服务管理一个共享工程，点位定义有稳定 `id` 与 `station`，尚无显式 `project_id`。工程、站点、画面不是同一对象；不得把站点字段、页面页签或来源连接当作独立工程身份。多工程隔离/切换未实现，跨独立工程引用不在本节已支持范围内。
- **归属与引用**：画面绑定和虚拟点 `inputs` 引用稳定 ID，显示名称不是身份。引用不改变输入点归属、不复制输入点；同工程跨站虚拟依赖已支持。2026-10-29起，普通工艺图、公共实例和工艺资料导入均可引用操作者授权范围内的跨站变量，保存统一走process授权校验；变量原归属、历史和存储周期保持。无权引用或不存在的ID拒绝，不能由画面可见性扩大变量权限。
- **显式批量分站（2026-10-29）**：`ownership` 用例经 `POST /api/v1/points/ownership-preview` 与 `ownership-commit` 提供实际归属调整。只有全站开发权限可用；从非GIS业务画面的解析后节点和箭头条件引用提取候选。单站引用仅作建议，多站共享和未引用默认不迁移，不按名称推断、不复制变量。请求使用稳定ID、原定义revision和目标目录站名；预览令牌覆盖当前定义、画面、目录、依赖配置和actor版本，提交重新验证。整批只改Station，其他字段和画面文档不变；重名、失效目标、陈旧版本、站级存储策略和有站范围的自动化依赖阻断整批。派生公式按稳定ID保留并提示引用依赖。
- **分站备份与生效**：数据库模式在同一事务写入点表及唯一恢复记录；文件模式先持久化恢复JSON，再原子保存点表，备份失败不修改变量。恢复记录含原/新归属、前后revision、保留字段摘要及回退目标，载入回退清单仍经相同预览和冲突校验，不强制覆盖。保存仅改草稿，不自动Apply、不重写历史，也不承诺后续显式Apply过程的实时值连续性；应用后按新归属授权和采集。删除旧站必须通过非级联引用检查，运行配置仍引用旧站时阻断，先应用再检查删除。
- **派生结果**：A/B 站对同一 X 分别乘/除 10，应创建两个独立虚拟点，分别拥有 ID、站点、公式、单位及历史。`v[index]` 对应 `inputs` 的顺序，输入是被引用点的工程值。当前计算结果还经过输出点自身倍率/偏移；示例公式使用默认倍率 1、偏移 0，不能无意重复换算。派生不修改 X，任意公式不提供自动逆向设备写入。
- **计算权威**：`points` 保存定义，`runtime.Apply` 验证依赖和编译有界公式，Go runtime 按依赖顺序计算。缺失依赖、循环和不合法公式不能以成功激活处理；保存配置不等于应用。Flutter、画面或脚本入口不得另算业务结果代替同一后端用例。后台运行不依赖某张画面打开；Go 进程停止后的持续运行不在此保证内。
- **质量与历史**：缺失、坏质量、陈旧输入或计算失败不得产出正常有效值。当前虚拟点以 `bad` 和空值表达无效；存储允许保留异常记录及其质量，不能误写为零或 GOOD，也不能将“保留异常证据”改述为“不保存异常”。历史冻结当时的值、单位、站点、质量、源/接收时间及配置版本摘要，后续改公式不重算旧历史；摘要不等同于已提供完整历史公式版本还原功能。
- **按站存储**：站点策略选择归属于该站的派生点，支持独立启停、周期、变化过滤、点位集合与保留天数；引用 X 不自动开启 X 的存储。站点策略不得直接接受其他站的点位并重贴本站标签。当前数据写入同一工程的 SQLite，以站点和点位 ID 区分；这不是每站独立数据库、独立用户授权或安全隔离。
- **写入边界**：虚拟点只读；拥有引用或显示能力不产生物理下设权限。物理写入继续走统一受控写用例，不由计算公式绕过权限、范围与确认状态。

后续修改必须保留“同源跨站派生、各站周期互不干扰、质量传播、旧历史不重写、拒绝跨站误存”的回归。变量使用位置反查、独立多工程与跨工程共享不能标为当前已有能力，也不在本节预设尚未确认的设计。

## 核心流程 A：用户添加点位到历史导出

入口为 desktop/web 用户，通过统一客户端。
1. 添加来源与点位/导入列映射，前后端校验稳定身份、站点、类型、单位、可写目标及换算。
2. 保存配置成功产生持久配置版；用户选择应用后发布运行版，失败保留上一有效版。
3. adapter 接收样本，保留源时间/质量，经换算写运行态；UI 展示实时/离线/缺失。
4. 独立存储策略按周期/变化/条件创建采样帧，有界入队；仅持久提交后算落库成功。
5. 用户按工程/站点/点位、时间、数值、质量筛选历史，读取分页统计/降采样图表。
6. 导出任务冻结条件/语义并异步处理；完成后文件可下载/保存，Excel 重读核对源行及类型。

失败/恢复：配置冲突拒绝、协议错误可见、断线值陈旧、存储缺口可查、任务取消区分已提交结果。验收包含真实文件重读以及单独的现场协议测试。

## 核心流程 B：后台条件事件与受控动作

入口为后台规范化样本/定时扫描，无 UI 会话依赖。
1. 规则引用稳定点位 ID，批次/新鲜度要求显式；缺失/BAD/陈旧输入产生 unknown。
2. 纯规则检查 AND/OR、持续时间、防抖、成立/恢复边沿及冷却，生成唯一执行身份。
3. 多步动作调用 control/storage 用例。下设重新校验当前权限、目标、范围和编码版本；快照绑定事件输入/运行版本。
4. 设备发送、ACK 和新鲜读回分开；存储队列接受与数据库提交分开。
5. 每步记录结果及部分成功，不承诺跨设备与数据库原子事务。
6. 重启恢复未决执行，查询/对账已发生的动作；结果未知不盲目重放；安全存储可按身份去重。

验收：同时满足、条件抖动、持续成立、恢复、重复样本、乱序、坏质量、脚本超时、队列满、写入未知、部分成功及进程中断。

### 工艺资料迁移（2026-10-29）

2026-10-30 可选父子导航迁移：版本1 JSON包增加 `navigation:{enabled,nodes}`，叶子以 `screen_key` 引用包内画面键，父项仅展示分组；不改变真实 station 键或编辑态站点平铺。请求 `navigation_target:{mode,revision}` 必须明确 create/replace/skip，UI默认skip，替换既有自定义树须用户确认；create只允许未启用且空树。catalog返回当前导航Config。预览将全部叶子解析为实际稳定画面ID，共用navigation公开校验，现有树与修订纳入token；非法树、缺目标及版本冲突在提交任何写入前闭锁。画面逐项保存后才调用navigation.Save；中途画面失败不发布缺目标菜单，菜单存储失败保留真实部分结果供重试，不承诺跨模块事务。此扩展仅支持JSON，XLSX/CSV不静默丢弃导航。

旧同批画面可显式批量选 `screen_targets[key].mode=update_imported`：只按非空import_identity、画面key和映射目标站生成原稳定ID，不按名称猜测；目标必须存在且Station/Kind相同，缺失不自动新建。预览返回实际旧/新文档及当前revision，token绑定旧文档，提交前并发编辑要求重预览。首次导入继续显式create；升级不删除旧站或已活MQTT变量。

`internal/transfer`负责迁移用例编排，通过points、process、stations公开服务保存，不绕过归属、revision和授权。HTTP `/api/v1/process-transfer/{catalog,decode,preview,commit,export}` 为薄适配器；Flutter开发入口共用向导，不承担绑定判定。只允许工程能力，导出还要求导出权限。画面、变量、绑定可独立迁移或组合；JSON完整包、三表XLSX及单类CSV采用版本1结构，允许旧单图JSON读入。布局素材、图片、背景渐变和透明度随画面保留；XLSX素材分块置于隐藏辅助表，用户可编辑列覆盖对应属性。

移植身份采用画面key、元素ID、属性及变量key；真实点位ID不直接跨工程沿用。站点与数据源须显式映射，站点创建须明确选择。变量处理分自动精确匹配、新建、更新和引用；自动匹配仅接受完整来源ID、topic、source_path唯一且类型/单位一致，不按名称猜测。候选定义缺少类型、归属或来源时保持待处理，不补造现场配置。绑定operation为空或keep保留，set指定目标，clear显式解绑；箭头clear保留条件逻辑。仅导布局更新时按元素ID和条件语义保留旧绑定，意义变化报冲突，新图保持未绑定。

预览不写入，提交校验请求及当前状态生成的预览令牌，并对变量/画面执行revision校验。稳定导入身份支持重复提交跳过，明确选择另一组副本才生成新身份。提交采用逐项真实结果，允许部分成功；不承诺整批事务。失败或未确定条目可导出含映射的retry_request，再导入后重新预览，已成功条目幂等跳过。保存变量定义不等于应用运行配置、连接数据源或物理下设。公共引用导出须显式确认展开为独立布局，来源工程不变。手工保存、导入和MCP沿用同一授权跨站引用规则。

开发端从画面文件菜单和变量工具栏进入；提交成功后刷新站点、变量和画面目录，不覆盖已打开的未保存草稿。绑定清单可定位元素；大量条目分页和搜索。交付画面及候选资料与应用分目录保存，不在升级时自动写入现场工程。验证和使用步骤见 [工艺资料迁移验证](process-transfer-verification.md)。

### Installation-key registration inventory

Local identity settings can retain manually owned CSR public-key registrations;
this is not a mobile authentication channel. Approval never grants access until a
separately verified transport is implemented. See [device registration records](device-registration-records.md).

## Explicit device certificate pins (development checkpoint, 2026-10-31)

Local-only certificate approvals use a separate versioned identity-store document,
not CA-chain trust or Android hardware attestation. Registration reapproval revokes
the corresponding certificate approval; each certificate approval has a fresh
generation. The first checkpoint does not connect a mobile listener or grant access.
Transport/session integration and acceptance gates are specified in the
[device certificate channel contract](device-certificate-channel.md).
