## 手机首次登录与一键审批（2026-11-02）

用户确认的普通流程是首次账号密码＋图形验证码登录后自动申请，本机管理员批准一次，之后设备正常登录。`identity/device_login.go`在密码及已启用MFA通过后，从实际TLS叶证书提取安装公钥及账号归属，持久生成pending登记，不创建登录会话。重复提交同一账号、同一叶证书只返回`device_approval_pending`，每账号最多8条待审，全局沿用256条设备上限；其他账号不能接管申请。Flutter收到该错误码显示“设备正在审批，请等待管理员批准”，不显示密码错误，清除口令并刷新单次图形验证码。批准后重新登录。

设备申请复用`DeviceRegistration`的可选`login_leaf_pem`，原CSR登记兼容。仅本机近期管理员会话通过POST `/api/v1/security/devices/{id}/approve-login`携带revision执行一次批准，在同一事务CAS更新登记、批准精确叶证书、生成审批代次并写审计；任一步失败整体回滚。期限跟随安装证书（默认约10年，可撤销）。手工CSR和证书管理保留高级用途，普通用户不需要导出、转交或填写设备码。停用登记/撤销证书使现有会话失效，不自动重新申请或恢复权限；公网永久只读约束保持。

## 公网图形验证码（2026-11-02）

按用户确认，公网 Web 与安卓统一使用账号密码加后端生成的轻量图形验证码，不强制新账号绑定验证器。`server/login_captcha.go` 使用固定 dchest/captcha 1.1.0 本地生成5位数字PNG，不调用第三方服务；GET `/api/v1/auth/captcha` 返回随机ID、图片与到期时间，不返回答案。挑战2分钟有效，提交即消耗（答错也消耗），绑定实际TCP来源及已验证设备叶证书；转发头不参与绑定。每来源刷新间隔1秒、最多4个待提交挑战，全局4096挑战/来源状态与8个图片生成槽；重启即失效。POST login 必须携带 `captcha_id` 和 `captcha_answer`，先校验图片答案再执行密码计算及既有登录限制，失败继续计入自动封禁。响应禁止缓存；刷新失败不能提交空挑战。

## 设备台账（2026-10-28，首版）

### 自动状态实现

用户要求可选故障/运行两个点位及简单公式，变量选择与公式配置仅开发态。由equipment拥有绑定和判断规则，引用已有稳定点位ID，不复制变量、不改变原站点/存储归属。runtime通过公开端口提供同一批次的已授权工程值、质量、时间与连接健康，equipment在锁外作有界纯计算；Flutter仅展示结果，不实现第二套判断。配置接口仅工程师可写，绑定点位仍须存在并在操作者范围内；读取结果同时检查设备及引用变量权限，跨站绑定不扩大访问范围。

运行端按当前列表/详情批量读取设备状态，限制设备数与绑定点位数，不传全库值、不执行任意脚本。初版按请求计算，无界后台全设备扫描不是前置。故障成立优先；故障未成立（或未配置故障）且运行判断有效时，运行公式真/假对应运行/停止。配置了但缺失、坏质量、陈旧、离线或计算失败的必要输入导致未知；仅故障点未触发且无运行点不能推断停止。完全未绑定显示未配置。网络失败时前端退役旧实时结果并显示离线。结果携带配置revision和判断时间，旧响应不能覆盖新列表/配置；新能力不下设、不自动存历史，后续告警需独立用例。

实际接口为`GET /api/v1/equipment/status?ids=...`，单次1–100设备、最多200个绑定引用，返回设备ID/revision/state/reason/evaluated_at，不返回原始变量值。`runtime.ReadPointsFor`统一校验点位及虚拟依赖权限、质量、陈旧与MQTT连接状态。非开发身份的档案响应隐藏signals；结果读取仍复核所引用点位权限，无权限或缺失时返回未知。表达式仅允许x、有限数值、算术/比较/布尔组合，限256字节、64 AST节点、16层，不允许函数/索引/循环/IO；布尔值按1/0，非有限数或除零为未知。故障和运行分别最多一个输入。配置保存即对后续状态查询生效，不额外应用整个采集配置。

状态接口缓存紧凑绑定索引，档案/图片成功保存后失效，失败保存保留旧索引；不在每次轮询重读PG整本档案。Flutter当前页面按2秒批量读取、5秒超时，切页/配置revision变化退役迟到结果；断网退役旧状态显示离线。当前为按需同步计算，尚未做多人长期容量验收，不据此宣称5000变量/50并发已验收。

设备编号在工程内不区分大小写唯一，稳定ID由后端生成；保存校验站区存在、字段限额与revision，冲突409且前端保留草稿。已有图片不能通过普通档案JSON伪造或覆盖。最多5000份档案，每页最多100条（UI 50），属性最多32项。按用户反馈，台账不依赖现场填报运行/维修状态，UI不提供人工状态字段、人工状态统计或筛选；新建档案不默认在用。旧status仅作为兼容字段原样保留，不解释为实时状态。首页汇总授权范围内登记设备数、已有档案的站区数与类别数，不受当前列表筛选影响。

## 2026-10-02 跨架构浮点换算

工程值的合同是两次 binary64 舍入：先 `float64(raw * scale)`，再加 offset。Go 编译器允许跨语句融合乘加；ARM64 首轮CI真实暴露了大偏移抵消错误接受与十进制过零误拒绝。运行态采集、整数逆算校验、浮点逆算回环使用同一个 `engineeringValue`，显式乘积转换禁止FMA融合；不放宽可表达性、物理读回或质量判定门槛。原回归与新增对照 `math.FMA` 的向量共同保留。

Argon2id密码、8小时绝对/30分钟空闲会话、摘要token、Cookie/CSRF、登录限流、改密/禁用/改授权撤销已实现；自动runtime/SSE/job轮询不续空闲。TOTP、单次恢复码、管理员重置及密钥加密/目录权限已实现。远程实际TLS模式强制MFA，未完成绑定前只允许会话和MFA引导。显式 `--identity-local-setup` 仅回环HTTP，拒绝代理头，用于本机首次建号和评审；不会创建默认密码。桌面自启携带身份参数，拒绝复用旧匿名健康服务。

按授权裁剪点位/公式元数据、实时/SSE、历史/统计、画面绑定/跳转、菜单；额外共享画面包含静态文字，不附带外站数据。文件任务绑定owner/授权版本，排队执行和下载重查；规则绑定显式执行身份，控制在发送前再查，撤权后不伪造已发送命令的撤回。安全变更和受控操作留本机审计，写操作前审计失败拒绝；审计不是外部不可篡改记录。

正式KP可组合统一身份，可信verifier提供 `mfa_verified` 和 `authenticated_at`，以配置中的稳定user_id关联已建账号，KP实例与统一会话双重校验；不能与用户名试验模式组合。Flutter提供独立账号安全/权限管理，非工程师只进入用户监控端。首版操作员不额外开放开发或控制动作，设备下设仍需control明确授权。

本批验证及部署见 [security-verification.md](security-verification.md)。以下设计中尚未实现的Passkey/OIDC、端类型策略、局部发布、双人批准、外部审计/备份及实际网络运维继续作为目标；不可据本批测试认定公网已可开放。

### 身份、角色与范围

授权依据为「稳定用户身份 + 明确动作 + 工程/站点/资源范围 + 会话与安全策略」，默认拒绝；IP、显示名称、菜单位置及前端当前站点均不产生权限。每次请求和实际执行都验证权限，规则参考 [OWASP授权建议](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

预置角色只是可审阅的权限集合，不把单个AllowWrite布尔值扩展成更多前端判断：

用户在2026-10-27最终确认：保留工程师角色，工程师可以开发，其他用户不能开发，并已授权实施。本节据此修订，取代上一轮“任何用户都无开发权”的方案。工程师必须显式授权，管理员不自动兼任工程师；角色可组合，但授权管理不能隐式自提权。以下为完整目标，当前具体边界以上述已实现合同为准。

| 预置角色 | 默认能力（均受授权范围限制） | 需要另行授予 |
| --- | --- | --- |
| 查看员 | 使用Web/用户端查看获准画面、实时值与历史 | 导出及其他已发布业务动作 |
| 操作员 | 使用Web/用户端执行获准的日常业务动作 | 已发布业务功能中的设备下设、用户管理；开发能力不可授予 |
| 工程师 | 获准范围内的画面、点位、菜单、公式、规则及来源开发配置 | 设备下设、用户管理；全局发布须工程级开发授权 |
| 安全管理员 | 用户、角色、范围、会话及安全策略管理 | 设备下设；授权变更须留审计且不可越出自身可授予范围 |
| 审计员 | 获准范围内的审计与执行记录 | 批量导出；不含业务修改、开发或删除审计 |

用户可授予动作限于已发布业务功能，如 `screen.read`、`point.read`、`history.read/export`、`control.write`、`user.manage`、`role.grant`、`audit.read`，并受工程/站点/资源范围限制。Web及用户端访问可分别配置，但端类型不能仅靠客户端自报、User-Agent或自定义请求头认定，须在服务端认证/会话策略中约束；两种入口共用业务授权。

`screen.edit`、`navigation.manage`、`point.edit/reference`、公式编辑、`runtime.activate`、`source.manage/connect`、`rule.edit/enable`、`storage.manage`及工程导入/开发素材编辑属于工程师开发能力，普通用户与仅有管理员角色的身份不可调用。旧AllowWrite、KP operator、客户端参数和MCP写开关不能隐式取得工程师能力。用户的数据分析文件导入/导出与工程配置导入分开。后端检查明确能力与资源；授权管理要求近期认证和审计，角色修改不能超出自身可授予范围或无记录地自提权。

非工程师界面不提供开发工作台、编辑器及开发菜单，不能用 `?view=development` 等直链进入；后端独立检查开发能力，工程师有权限时才可操作，不能仅隐藏前端入口。共用业务用例保持同一权限契约。MCP开发写工具除独立写开关外也要求工程师能力，普通用户凭据不能调用。用户管理界面独立于开发工作台，工程师开发不自动获得账号管理或设备控制权限。

第一阶段仍为单工程内多用户、多站授权，不承诺多租户隔离；多工程继续归PROJECT-01。工程、用户及站点授权需要稳定ID。当前多个结构以station字符串表达站点，正式站点授权前先定义稳定station_id注册与兼容迁移，保留旧名称及历史归属快照；重命名或点位移站不能隐式改授历史访问权，不能以字符串重写全部历史完成迁移。

用户管理包括创建/邀请、启用/禁用、修改角色与范围、重置凭据、查看和撤销会话；不提供开放注册或默认密码。首管理员经本机一次性引导或受控安装流程建立，恢复流程留审计，避免删掉最后一个有效管理员后无恢复入口。新密码存储优先Argon2id，既有bcrypt通过版本化策略逐步迁移；不得记录明文或截断密码。支持长口令、泄露/常见口令拦截、账号与来源组合限流、统一失败提示和有限退避，避免攻击者靠反复失败永久锁死账号。账号禁用、凭据重置和降权撤销旧权限/会话，长连接同步失效。参考 [OWASP认证建议](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

浏览器优先短期服务端会话与HttpOnly Cookie，配置空闲与绝对期限、会话轮换、当前/全部终端退出。公网访问要求MFA；特权用户及远程控制优先抗钓鱼Passkey/安全密钥，离线内网可选本地TOTP及受控恢复。企业OIDC与KP只负责可信身份接入，均映射稳定user_id及同一授权服务；MFA强度要有可信证明，不能因走另一登录入口绕过。桌面与MCP使用独立有期限凭据及系统安全存储，不复用长期管理员口令。

### 数据与画面授权边界

1. 列表、详情、搜索、数量、统计、实时/SSE、历史、文件预览/下载及MCP全部采用后端授权范围；客户端station参数只能进一步缩小范围。工程配置批量保存及全局apply要求工程师能力，并验证全部受影响资源和版本；仅有局部站点权限不能全量替换其他站配置，全局操作须工程级开发授权。
2. 全工程实时快照可以内部共享，输出必须先按权限裁剪；不得把仅按时间缓存的全量JSON直接交给局部用户。缓存键包含范围与权限版本，撤权关闭/更新SSE并清理前端旧数据，重新连接不能取回旧授权数据。
3. 菜单分组只组织展示；服务端返回用户可访问的叶子及必要祖先，点击父组打开首张可访问画面。GIS跳转重新验证目标画面访问权；禁止只在UI隐藏未授权入口而保留可读直链。
4. 公共画面与跨站GIS不自动授予引用变量的读取权限。目标画面、引用值和配置元数据分别判权；无权限不输出值、绑定细节或敏感站名。跨站共享画面的可见静态内容也须明确授权/审阅，不能声称仅遮数值就隐藏了画面中人工文字。
5. 虚拟点的归属与输入引用继续分离：可查看已授权派生结果不代表可读取上游原值或公式；公式开发只对工程师开放，跨站依赖须验证全部输入的引用权限。派生结果的共享须显式授权，不把计算作为隐式跨站数据通道。
6. 上传、预览、异步导出及下载绑定稳定创建者、工程、数据范围和权限版本。排队、执行、下载均复核当前权限；撤权后停止未开始的任务并拒绝文件下载。历史授权按保存时归属处理；猜测job_id或point_id不能获得其他人的文件/数据。共享任务必须显式授权。

### 设备动作和后台执行

保存开发草稿、发布运行及启用规则要求相应工程师能力与范围。设备下设为单独的control.write能力，工程师或管理员均不自动获得；普通操作员只能操作已发布的既定目标，不能修改点位映射、公式或规则。直接下设及既有后台规则动作都经后端受控写入服务，检查目标、当前授权、允许范围、配置版本与命令ID；需要时执行近期认证/二次确认，关键现场动作可配置双人批准。

后台规则使用显式、受限的执行身份及授权范围，记录发布人、版本与执行主体，不能在用户退出后继续借用其无限权限。撤销执行身份阻止新动作；撤权发生在排队期间须在实际发送前再次检查。已发送动作保留未知/应答/读回状态并对账，不以退出或撤权伪造撤回成功。共享采集和存储不因普通查看用户退出而停止。

### 公网、内网与运维

- 本机开发模式仅回环且明确标识无登录，不得被反向代理转成公网匿名入口。内网服务同样启用身份、TLS和权限，不因来源是内网IP或回环代理而绕过。保留现有联网启动拒绝规则，禁止静默降级。
- 推荐公网入口只暴露HTTPS 443，经受控入口/反向代理进入已认证服务；OT设备、MQTT broker、数据库与管理端口不直接暴露公网。公共展示如确有需求，另建显式只读、最小数据投影，不能等同完整HMI匿名访问。远程维护优先VPN/零信任访问入口与MFA，控制链路按区隔离。
- 目前Go必须实际承载TLS，不能直接假设代理终止TLS后转HTTP可用。第一步可采用TLS透传或代理到Go的受信HTTPS；若后续支持TLS终止，必须配置可信代理地址/跳数、覆盖外来Forwarded头、精确公共Host/Origin及仅代理可达的后端监听，并独立测试。禁止通过篡改Host把联网访问伪装成本机模式。
- 限制每账号/来源/全局登录、API、SSE及文件任务资源；覆盖请求体/解压体积、行数、CPU、执行时间、队列和磁盘容量。输入验证、参数化数据库访问、路径与上传类型校验、CSV公式安全、CSP及安全响应头需针对Flutter/WASM/Cesium/KP嵌入实际验证，不能直接放宽到任意来源。
- 来源连接由获准工程师配置，身份verifier等部署目标由受控部署流程管理，均受网络允许范围约束，不因用户管理员角色而开放；正常工业网段作为明确允许项，不以“禁止一切私网”破坏采集。MQTT使用独立最小权限身份、TLS与topic ACL，密钥只在后端私密存储，前端/API/日志不回显。
- 审计记录主体/会话、动作、资源范围、授权决定、配置前后版本、请求/命令关联ID、来源和结果；不记录密码、token或全部敏感报文。特权动作审计落盘失败应拒绝新操作；普通读取的日志故障不阻断既有设备安全运行。限制审计读取/删除，集中留存及完整性保护，不将同机日志称作不可篡改。
- 使用低权限服务账号、私钥/数据目录ACL、数据与Web静态根目录分离、受控更新和依赖漏洞检查/SBOM；备份加密并验证恢复、证书到期告警、磁盘/异常登录监控。防护和限流不能阻塞既有采集/保护回路；安全与可用性一起验收。

### 模块与实施顺序

保留Go模块化单体。计划新增 `backend/internal/identity`（用户/凭据/会话）、`authorization`（动作/范围/策略版本）、`audit`（安全事件）；名称是计划路径，尚未创建。server只解析认证凭据、建立Actor并调用公开用例；各业务用例通过授权公开接口判权和查询约束，避免绕过HTTP后失去保护。存储/analysis/runtime/process采用受约束公开接口，Flutter仅据能力控制界面；现有KP桥通过身份适配器接入，不复制用户库。用户/角色管理UI计划置于 `app/lib/features` 的全局管理入口。

实施顺序：① 工程师与普通用户的开发边界、稳定站点身份与兼容迁移、用户/角色/范围/会话权威及审计；② 所有业务入口和数据投影接入，补普通角色拒绝开发/工程师正向操作、历史/导出/SSE/MCP/规则执行越权回归，形成独立用户管理界面；③ MFA/可信身份接入、网络边界与运维配置，做真实内网/公网验收。前两阶段没有完成覆盖前，不宣称系统可以安全公网部署。

验收必须包含非工程师角色（含单独管理员）的开发路由/开发接口/MCP开发工具拒绝、工程师正向开发、伪造端类型、旧operator/AllowWrite及自定义角色无法隐式获得开发权，以及同名跨站、未知ID、直链与批量越权、权限撤销后SSE/缓存/导出、跨站画面/虚拟引用、角色自提权、不同登录入口一致性、CSRF/Host/代理伪造、账号禁用/重启/恢复、限流和资源耗尽、规则绕过控制权限的失败路径。设备动作使用模拟端验证，不以安全测试触发现场控制；公网开放另按实际拓扑验收。工作状态只在AI_BOARD的SECURITY-01维护。

## 2026-10-02 缩放与事件回归补充

本轮不新增层次：`runtime/control.go` 权威处理工程值逆算与物理原值读回，`runtime/policies.go` 权威维护存储周期/变化基线与分作用域错误，`runtime/rules.go` 提供保存及预览共用校验。验收矩阵见 [专项回归](focused-functional-tests.md)。

写入需在持久意图之前验证原值类型及正向换算回环；不可表达目标、下溢、溢出、偏移抵消不得作为成功写入。读回在原值域比较，INT/BOOL 精确匹配，FLOAT 仅容许浮点计算舍入余量，不能让大工程偏移放宽物理目标。INT 原值范围为 ±9007199254740991。非有限原始数字保留为诊断字符串 NaN/+Inf/-Inf，工程值为空且质量 bad，避免污染整个 JSON/历史查询。

重复保存同一存储策略或重复 storage_start 不重置采样时钟/变化缓存。未改变执行语义的规则（包括仅改显示名称）保留边沿、持续及冷却状态；真正改变条件/动作/启用/作用域/时序配置会重新初始化该规则。保存、预览共用规则校验；缺失/null 条件阈值拒绝，不默认零。存储、规则审计、命令审计错误按作用域保留，别的成功操作不能解除。

历史仍只有源时间和接收时间，未新增落库时刻；重复周期快照保留原采集时间。重启恢复策略但不恢复运行样本，规则禁用、按来源启动策略连接；新样本到达后可按原策略存储。脚本依旧是有界声明式动作序列，不执行任意系统进程。当前进程最多保留 256 条存储/审计失败详情；超限警告保留至重启，不因其他操作成功而清除。

Flutter 桌面发行包会探测已有本机 Go 服务，否则启动包内 sidecar；平台文件能力经条件适配。2026-10-26 桌面启动传入 `--auto-port --endpoint-file <本次临时目录>/endpoint.json`：Go 优先绑定 127.0.0.1:18080，失败时绑定 127.0.0.1:0，并持续持有同一个 listener，避免探测与实际监听之间的竞争。Go 原子写入实际 URL/PID，Flutter 有界读取、校验本次子进程 PID 与回环 HTTP 地址后检查健康；`platform/backend_endpoint.dart` 给 API/SSE/文件及原生 GIS 提供同一地址，启动结束清理临时描述文件。已有健康 HMI 服务复用语义保持；显式 API_BASE_URL、Web 同源和远程认证/TLS/KP 部署不启用该降级。端口在打开工程存储之前绑定。最终包同时携带 Flutter Web，可在本机浏览器访问同一服务。后端采集/事件/存储不依赖页面；退出桌面时自有 sidecar 的实际生命周期仍需平台人工验收。默认仍只允许回环监听；本轮新增的显式认证/TLS模式见上节，部署与真实内网验收单独进行。

## 模块与职责

| 能力/边界 | 实际路径 / 后续拆分 | 公开契约 | 权威归属/允许依赖 | 禁止/验证 |
| --- | --- | --- | --- | --- |
| Flutter 展示 | app/lib/features/、main.dart | 用户操作、DTO、视图状态 | 服务器数据由 Go 权威；允许统一 API/平台适配 | 不接 PLC/MQTT/SQL；analyze、widget 与桌面/Web 流程 |
| 平台适配 | app/lib/platform/ | 窗口/文件/sidecar 接口 | 平台能力由适配器拥有 | Web 不导入无条件 dart:io；两种构建 |
| API/传输 | backend/internal/server/；transport 后续按需拆分 | HTTP DTO、稳定错误码、实时订阅 | 认证/解析/响应，调用用例 | 不做公式/换算/重试策略；handler 契约测试 |
| 点位配置 | backend/internal/points/ | 工程/站点归属、点位 CRUD/应用 | 配置持久权威；运行配置明确激活版本 | 名称不是 ID，保存不表示已采集；校验/持久恢复测试 |
| 采集与运行态 | backend/internal/acquisition/、runtime/ | NormalizedSample、点位快照/质量/时序 | 源事实经 adapter 进入内存权威 | 不从 Flutter 计算工程值；多来源契约/乱序测试 |
| 条件与虚拟计算 | backend/internal/runtime/；events 后续按需拆分 | RuleDefinition、RuleExecution、动作意图 | 纯条件/依赖规则不依赖框架；用例调动作接口 | 不识别厂商 JSON、不直写数据库/设备；边沿/质量/循环测试 |
| 物理控制 | backend/internal/runtime/；control 后续按需拆分 | WriteCommand、每步确认状态/对账 | 用例统一鉴权、版本、范围、codec 与命令身份 | 不将发布当执行、不重放未知；ACK/读回故障测试 |
| 独立存储 | backend/internal/storage/ | StoragePolicy、SampleFrame、query | 历史语义由存储模块维护；冻结配置/单位/时间 | 不依赖检测业务、不无界缓冲；断库/重启/缺口测试 |
| 分析与导出 | backend/internal/analysis/ | 筛选、分页、统计、ExportJob、ImportPreview | 查询/文件任务由用例协调，查询快照可追溯 | 不把 Excel 当业务数据库；大数据/取消/文件重读测试 |
| 基础设施 | MQTT 位于 acquisition/；SQLite 位于 storage/ | MQTT、KingIO、存储、文件接口实现 | 依赖通用公开类型；装配入口选具体实现 | 厂商字段不进领域；协议/事务测试 |
| 装配 | backend/cmd/server/ | flags/env、生命周期/health | 连接具体实现、显式配置监听/资源 | 不包含业务判定；启动/关闭/health |

点位定义以原子替换 JSON 持久化；历史、配置策略、写入意图和执行记录使用 SQLite WAL。runtime 统一编排，厂商 JSON 只在 acquisition 解析，文件操作只在 analysis。未来拆出 control/events 或支持其他数据库时维持当前权威归属。工程值只由 Go 计算。

源码依赖方向：展示→统一客户端；transport→用例；用例→纯规则/公开端口；adapter 实现端口；cmd 装配。运行时消息流不作为允许越层依赖的理由。

## 数据及状态合同

- 来源连接、工程、站点、稳定点位 ID 与显示名称分别建模。发现身份明确来源/站点/源路径；不能用动态数组下标代替稳定设备身份。
- 原值、工程值、单位、质量、源时间、接收时间和陈旧状态分别记录。坏质量或缺失不能当零/GOOD。
- 保存定义→验证→激活运行版→执行动作是不同操作；版本冲突拒绝旧配置覆盖。
- 物理动作：accepted/sent/acknowledged/readback_confirmed/failed/unknown；未知提供对账，不自动重写 PLC。
- 历史帧冻结相关单位、换算、成员及配置版本，后续修改不重算旧历史。
- 导出冻结查询条件和读取边界；重复分页、取消、超大数据和失败文件有明确结果。
- 本地默认为回环监听；远程访问先建立认证/权限及安全部署合同。开发 CORS 必须显式白名单，不能代替鉴权。

## 变量归属、派生与存储

本节是已确定变量语义的技术合同；产品目标仍以 [agent.md](../../agent.md) 为准。实际验证和代码索引见 [变量与存储核验](variable-semantics-verification.md)。

- **范围与身份**：当前服务管理一个共享工程，点位定义有稳定 `id` 与 `station`，尚无显式 `project_id`。工程、站点、画面不是同一对象；不得把站点字段、页面页签或来源连接当作独立工程身份。多工程隔离/切换未实现，跨独立工程引用不在本节已支持范围内。
- **归属与引用**：画面绑定和虚拟点 `inputs` 引用稳定 ID，显示名称不是身份。引用不改变输入点归属、不复制输入点；同工程跨站虚拟依赖已支持。2026-10-29起，普通工艺图、公共实例和工艺资料导入均可引用操作者授权范围内的跨站变量，保存统一走process授权校验；变量原归属、历史和存储周期保持。无权引用或不存在的ID拒绝，不能由画面可见性扩大变量权限。
- **显式批量分站（2026-10-29）**：`ownership` 用例经 `POST /api/v1/points/ownership-preview` 与 `ownership-commit` 提供实际归属调整。只有全站开发权限可用；从非GIS业务画面的解析后节点和箭头条件引用提取候选。单站引用仅作建议，多站共享和未引用默认不迁移，不按名称推断、不复制变量。请求使用稳定ID、原定义revision和目标目录站名；预览令牌覆盖当前定义、画面、目录、依赖配置和actor版本，提交重新验证。整批只改Station，其他字段和画面文档不变；重名、失效目标、陈旧版本、站级存储策略和有站范围的自动化依赖阻断整批。派生公式按稳定ID保留并提示引用依赖。
- **分站备份与生效**：数据库模式在同一事务写入点表及唯一恢复记录；文件模式先持久化恢复JSON，再原子保存点表，备份失败不修改变量。恢复记录含原/新归属、前后revision、保留字段摘要及回退目标，载入回退清单仍经相同预览和冲突校验，不强制覆盖。保存仅改草稿，不自动Apply、不重写历史，也不承诺后续显式Apply过程的实时值连续性；应用后按新归属授权和采集。删除旧站必须通过非级联引用检查，运行配置仍引用旧站时阻断，先应用再检查删除。
- **派生结果**：A/B 站对同一 X 分别乘/除 10，应创建两个独立虚拟点，分别拥有 ID、站点、公式、单位及历史。`v[index]` 对应 `inputs` 的顺序，输入是被引用点的工程值。当前计算结果还经过输出点自身倍率/偏移；示例公式使用默认倍率 1、偏移 0，不能无意重复换算。派生不修改 X，任意公式不提供自动逆向设备写入。
- **计算权威**：`points` 保存定义，`runtime.Apply` 验证依赖和编译有界公式，Go runtime 按依赖顺序计算。缺失依赖、循环和不合法公式不能以成功激活处理；保存配置不等于应用。Flutter、画面或脚本入口不得另算业务结果代替同一后端用例。后台运行不依赖某张画面打开；Go 进程停止后的持续运行不在此保证内。
- **质量与历史**：缺失、坏质量、陈旧输入或计算失败不得产出正常有效值。当前虚拟点以 `bad` 和空值表达无效；存储允许保留异常记录及其质量，不能误写为零或 GOOD，也不能将“保留异常证据”改述为“不保存异常”。历史冻结当时的值、单位、站点、质量、源/接收时间及配置版本摘要，后续改公式不重算旧历史；摘要不等同于已提供完整历史公式版本还原功能。
- **按站存储**：站点策略选择归属于该站的派生点，支持独立启停、周期、变化过滤、点位集合与保留天数；引用 X 不自动开启 X 的存储。站点策略不得直接接受其他站的点位并重贴本站标签。当前数据写入同一工程的 SQLite，以站点和点位 ID 区分；这不是每站独立数据库、独立用户授权或安全隔离。
- **写入边界**：虚拟点只读；拥有引用或显示能力不产生物理下设权限。物理写入继续走统一受控写用例，不由计算公式绕过权限、范围与确认状态。

后续修改必须保留“同源跨站派生、各站周期互不干扰、质量传播、旧历史不重写、拒绝跨站误存”的回归。变量使用位置反查、独立多工程与跨工程共享不能标为当前已有能力，也不在本节预设尚未确认的设计。

## 核心流程 A：用户添加点位到历史导出

入口为 desktop/web 用户，通过统一客户端。
1. 添加来源与点位/导入列映射，前后端校验稳定身份、站点、类型、单位、可写目标及换算。
2. 保存配置成功产生持久配置版；用户选择应用后发布运行版，失败保留上一有效版。
3. adapter 接收样本，保留源时间/质量，经换算写运行态；UI 展示实时/离线/缺失。
4. 独立存储策略按周期/变化/条件创建采样帧，有界入队；仅持久提交后算落库成功。
5. 用户按工程/站点/点位、时间、数值、质量筛选历史，读取分页统计/降采样图表。
6. 导出任务冻结条件/语义并异步处理；完成后文件可下载/保存，Excel 重读核对源行及类型。

失败/恢复：配置冲突拒绝、协议错误可见、断线值陈旧、存储缺口可查、任务取消区分已提交结果。验收包含真实文件重读以及单独的现场协议测试。

## 核心流程 B：后台条件事件与受控动作

入口为后台规范化样本/定时扫描，无 UI 会话依赖。
1. 规则引用稳定点位 ID，批次/新鲜度要求显式；缺失/BAD/陈旧输入产生 unknown。
2. 纯规则检查 AND/OR、持续时间、防抖、成立/恢复边沿及冷却，生成唯一执行身份。
3. 多步动作调用 control/storage 用例。下设重新校验当前权限、目标、范围和编码版本；快照绑定事件输入/运行版本。
4. 设备发送、ACK 和新鲜读回分开；存储队列接受与数据库提交分开。
5. 每步记录结果及部分成功，不承诺跨设备与数据库原子事务。
6. 重启恢复未决执行，查询/对账已发生的动作；结果未知不盲目重放；安全存储可按身份去重。

验收：同时满足、条件抖动、持续成立、恢复、重复样本、乱序、坏质量、脚本超时、队列满、写入未知、部分成功及进程中断。

## 2026-10-01 第一版实现合同

用户确认 Linux 先开发调试，Windows 最终构建。points 保有配置权威；新增 internal/runtime 编排规范化值、虚拟算术、条件规则与统一写用例，internal/acquisition 只处理 MQTT 协议，internal/storage 使用本地 SQLite WAL 保存历史和执行记录，internal/analysis 处理有界文件及串行导出任务，internal/server/platform.go 只转译 HTTP。

保存点位后必须 POST /api/v1/apply 才激活；激活检查虚拟依赖环、限长算术表达式并产生配置摘要。历史冻结点位身份、名称、单位、原值、工程值、质量、源/接收时间及配置版本。运行值不会持久重放。来源保存后显式连接；重启按已保存来源的启动策略连接，事件默认禁用。独立存储策略可恢复，采集/存储均不依赖 UI 会话或检测任务。

PUT sources、storage、rules；POST manual sample、write、snapshot、demo；GET runtime、history、executions、jobs；import upload→mapping preview→commit；export 绑定 seq 边界并通过 jobs 下载/取消/删除。配置旧版本写入拒绝，重复命令 ID 必须匹配原请求；意图先落盘，未知结果不重发。generic MQTT 下设仅能报告 sent/unknown，不能宣称 PLC 应答/读回；KingIO 按公开 KIO 合同提供相关 Qid 的终态 ACK 和后续新鲜物理读回确认，真实设备尚未验收；Kepware 仅支持读取。

限制：来源 32、点位 20000；每来源 MQTT 原始消息队列 128 条、运行样本队列 128 批，分别公开接收/处理/丢弃/排队计数；单消息 1 MiB；公式 256 节点、64 输入、无范围或循环；规则 200、每条 32 条件/16 动作；文件 8 MiB、解压 32 MiB、16 工作表/100 列/50000 行；查询最多 5000 行；导出队列 8、任务 64、单次最多 50000 行/30 秒。超限报错要求缩小范围。SQL 时间范围/站点/点位/质量/数值筛选为图表、统计、导出共同依据。初版未承诺任意 JavaScript、任意协议写入或全部目标交互。

### 第一版界面与打包合同

Flutter 通过统一鉴权客户端建立 SSE 订阅；初次目录版本对齐与显式操作后的单次查询仍使用运行快照接口，不再持续 HTTP 轮询；实时图表使用有界三分钟/1800 样本缓冲，默认选同单位曲线。历史图表展示当前分页数据，完整筛选统计和导出由 Go 查询；不能把当前页面当完整数据集。导入数据独立建历史目录，重启后仍可选择，不生成虚假的采集点。

显式启动的模拟工程为 30 站/90 点。可写模拟设定值在采集开启时周期读回，保留最近写值，停止后按陈旧时间降级；这不表示真实设备已确认。界面保持保存草稿、应用配置、命令发送、设备读回及报表生成/文件保存的区别。

桌面文件对话框与 Web 上传/下载经 app/lib/platform 适配。发行包包含 Flutter runner、Go 服务和 Web 资源；Linux tar 保留执行权限。最终包启动测试使用隔离的 XDG_DATA_HOME，验证自动 sidecar、同源 Web、模拟采集与独立存储，不连接生产设备。

### 2026-10-02 后端重建合同

本轮从可访问公共基线重新实现，不是遗失工作树的逐字恢复。点位批量创建 POST /api/v1/points/batch 一次校验、一次原子保存，最多 20000 定义。运行层激活后使用稳定 point_id 与 source_id/topic/source_path 索引；一个来源可承载多站，多个来源中的相同路径保持隔离。容量目标为 5 来源、30 站、每站 500 点，总计 15000 点；模拟/本地 MQTT 验证与现场容量认证分开报告。

GET/PUT /api/v1/storage?station= 与 POST /api/v1/snapshot?station= 固定请求的站点作用域；空站点为独立全局策略。站点策略持久化、点位引用必须属于该站；配置移动点位后旧站规则产生未知，旧站策略不会捕获新站值。规则可带 station；条件与写动作都在运行时重新检查所属站，存储动作使用规则自身作用域，重启仍禁用规则。历史样本冻结 station，历史目录按 point_id+station 保留迁移前后的记录；目录默认/上限 20000，返回 limit/truncated。导出 Job.station 与完整筛选边界在任务创建时冻结，后续界面切站不改变排队任务。

物理写入需通过 GET /api/v1/points/{id}/write-capability 返回的数值类型、工程值范围与原因校验；字符串物理写不支持。KingIO 要求 writable=true 且 rw_mode 为 W/RW；write_source_id/write_path 可独立指定，缺失时回退到读取来源/路径。来源保存 client_id、writer、ack_timeout_ms，凭据不属于来源或状态 JSON。测试用临时认证只经 adapter 连接参数注入，不加载客户凭据。

POST /api/v1/write 要求显式 value（缺失/null 拒绝），持久化意图后返回 accepted；4 个工作协程、最多 32 个排队任务、最多 64 个未完成命令，发布前复核活动版本与连接。ACK 等待不持有运行全局锁，不阻塞采集消费。命令字段 publish_state、ack_state、readback_state 分别记录发布、设备响应与读回，GET /api/v1/commands/{id} 可对账。同 ID 同载荷只返回旧结果，不重发；不同载荷拒绝。未发送的排队命令停机后为 not_sent；已经开始发布但终态不明的命令重启后为 unknown，不自动重放。只有相关 Qid、ProcessStep=100、Result=OK（大小写不敏感）算设备成功 ACK；物理读回另须读取目标、活动版本、类型、质量、目标值都匹配，且不是 retained、不是乱序、时间晚于本次发布。ACK 已到但没有新鲜读回仍为 acknowledged/unconfirmed，不能冒充 readback_confirmed。

## 总统计报表并发与回滚追加（2026-11-12）
