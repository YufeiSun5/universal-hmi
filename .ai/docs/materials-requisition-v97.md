# 请购四节点与办理链 v97

2026-11-16，用户授权实施并要求在 Web 评审。本轮在独立工程启动评审环境，不覆盖现场或 18153。当前状态以根 AI_BOARD 为准。

## 用户确认的范围

- 编制填写文字或上传 Excel，拆出工程项目名称、工程编号、请购时间、施工单位及动态明细，跳过只有序号的空行，到签字区域结束。复核可改工程字段、增删明细、修改数量、补充说明；确认提交记录本人编制签名。导入同时自动保存原 Excel 作为追溯附件，界面仅保留一个导入入口；不再单独显示“添加附件”。
- 需求时间保存 JSON，允许日期样文本、任意文字、对象或空值。界面自由填写，保留未编辑的原 JSON 值，不按列名强制解释日期；不根据“有/没有”“已领”等文字推断库存。
- 四项独立权限：编制 `materials_request`、审核 `materials_review`、批准 `materials_approve`、物资已阅 `materials_receive`。同一账号可以有全部权限并依次办理本人单据，不跳步。同节点所有具备权限的人共享待办，任意一人成功即完成。
- 编制提交 → 待审核 → 待批准 → 待物资已阅 → 已闭环。审核、批准可退回原编制人，原因必填；重提生成新内容版本，从审核开始。物资只确认看到清单，不是实物收货，不修改库存。
- 工作流岗位默认我的待办，可切换全部状态、本人、历史闭环查询。上述四种岗位均可只读浏览全部请购及历史版本；原库存、入出退转类及其凭证权限不扩大。
- 单据详情显示类似 Git 历史的办理链，每个节点显示岗位动作、人员、时间、退回原因及签名，展开可查看对应版本清单。当前及历史版可导出 Excel，签名使用当时的不可变资产。两个下载入口明确分开：“下载原始附件”返回上传原文件（备份/追溯）；“导出完整流程 Excel”生成复核后的数字化请购单、各节点人员/时间及签名；历史版按钮为“导出此版流程 Excel”。

## 实现边界

`backend/internal/materials` 负责状态机、导入解析、签名/附件引用及导出。`authorization/identity/pageaccess` 增补独立权限与页面准入。`server/materials.go` 仅解码和转发；Flutter `features/materials` 增加复核编辑器和链式详情，复用会话草稿、文件适配器、错误处理、个人签名与工作台样式。

所有正式新建/重提统一四节点，即使旧客户端省略 `workflow` 也不再创建单级流程；旧客户端缺少签名时明确失败，不能绕过编制确认。已有旧版记录不改写，不虚构缺失签名；历史待审批沿用原审批入口，旧退回单重新提交后进入四节点。旧格式测试数据只由 `_test.go` 的历史 fixture 生成，不在产品中保留新建旧流程的旁路。

状态字段：`review / approval / receipt / closed / rejected`。提交版本号只在重提增加，节点动作必须携带版本及预期阶段；沿用数据库事务、guard 行、操作 ID 幂等。首次成功后同阶段重复/竞争处理返回冲突，不会代办下一阶段。签名、操作者 ID/姓名、时间与意见写入版本中的追加步骤，跨版本不覆盖。

新增 `materials_requisition_assets` 保存申请版本和不可变资产引用；资产仍由现有工程 objects 文件存储承担。附件需编制人本人上传、最多10个，每个最多10 MiB；明细最多1000条，解析最大2000行/64列，解压上限64 MiB。附件显示名由服务端已存资产生成，不信任请求中伪造的元数据。备份仍须包含数据库与工程对象目录。

新增 API：`POST /api/v1/materials/applications/import`，返回工作表选择/解析结果、提示和原稿引用；上传不代表提交。`GET /api/v1/materials/applications/{id}/export?version=N` 导出当前或指定历史版。原提交与决策 API 增加请购结构和阶段参数。列表 `status=todo` 按真实岗位/状态过滤；既有入库选择器 `status=approved` 同时包括四节点已批准与闭环单据，入库继续单独确认。

Excel 重新排版为分行工程信息、动态明细、申请说明及四方签名，重复打印表头、长文本续行、页码与当前状态。单元格文字使用显式字符串写入，不执行导入公式或把文本作为公式导出。
