# KP 视觉兼容与原样加载 v56

用户要求加速时保留原貌，并提供了 KP 顶部标题、菜单和时钟重影的截图。本批仅交付 Windows/Web；没有安卓交付或现场部署。

## 修订

- 撤掉 v55 新增的站点名单和地图站区列表过渡页，恢复原加载动画与原 GIS；地图、顶部栏、菜单、字体及其布局不重新设计。
- 保留在轻量入口提前兑换 KP 一次性票据，避免界面冷下载超过 30 秒后兑换过期。
- 在认证成功后并行预加载两个原字体，和 Flutter 的实际请求复用同一响应。没有裁剪字库、替换字形或新增外部字体地址。
- KP 在线入口跳过 Flutter 离线 worker 的启动等待和 JS/WASM 双份预缓存；普通入口保持原行为。原 gzip、缓存重验证和访问边界保留。
- 修正老浏览器 CanvasKit 完整帧复制：只对 Flutter 画布的完整 2D 帧复制先清空旧像素，再执行原绘制。没有关闭 GPU 或改动地图渲染。

## 根因与验证

在本机 KingPortal 自带的 Chromium 110.0.5481.178 中，隔离 HTTPS 监控与实际 HTTP 父页面已复现用户截图的透明顶部栏重影。Flutter 3.35.4 的 `RenderCanvas.renderWithNoBitmapSupport` 使用 `drawImage` 复制完整帧，未清除旧的透明像素；改为 CPU 渲染不能解决，完整帧清空则能解决。

兼容处理限定 `FLT-CANVAS-CONTAINER`、九参数复制和完整目标画布；普通图像、部分复制及地图画布不清空，重复加载不叠加钩子。专项自动测试覆盖这些边界及普通入口 worker 行为。

候选版真实 Chromium 110 连续刷新时钟 10 秒后无重影，原透明视觉保留。字体仅请求一次，从引擎初始化后约 675ms 开始，提前到认证后的约 31ms；这是本机隔离测量，不是公网加载时间保证。完整中文字体仍约 13.6MB 压缩传输，慢网首次下载仍受带宽影响。

Go 全量 test/vet、Flutter analyze 和 623 项测试（2 项既有跳过）、7 项提前兑换、13 项 native/trial helper、18 项历史 KP 脚本、渲染专项及 5 项 GIS 包装测试通过。最终Windows/Web同源构建通过。实际Chromium110首次帧约1.66秒、兑换88ms；新版Chrome156在界面资源人为延迟35秒时兑换145ms、35.6秒正常进入。上述均为本机隔离记录，不能作为公网速度承诺。两端菜单悬停、10秒时钟刷新、数据总览/返回地图、90实时值读取、写403、关闭撤销及重新应用后旧授权拒绝通过。

v55→v56覆盖、重装和卸载保持5019变量、31画面、12表，以及账号、图片、批准证书、共享价格和KP配置；隔离进程停止、原快捷方式恢复。

## 升级

在监控服务器覆盖安装 v56，沿用原工程。后台重启后，联调授权会轮换；在“登录与安全→KP接入”重新复制“画面打开时”脚本，替换本机 KP 承载画面的打开事件，保存工程并刷新整个 KP 运行页。联调模式、固定账号及空白后台核验地址继续沿用。

本机 KP 调试通过后再迁到现场另一台服务器，仍按用户既定部署顺序执行；本轮没有提前要求最终现场核验地址，也没有修改现场、18153 或用户原画面配置。
