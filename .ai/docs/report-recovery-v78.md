# v78 报表恢复、协作与访问防护

2026-11-12。用户报告 Windows 打开热/电/水报表空白、切页等待45秒后无法继续操作，内网旧报表链接触发封禁，并追加多人误冲突、退出仍显示编辑、Web回车丢输入和运行端直接导出要求。产品母本仍为 [agent.md](../../agent.md)。

## 实现

- Windows 主机与报表改用 WebView2 原生消息通道；首次握手、加载失败、保存失败和等待超时分开处理。提供重试、重新加载与明确提示未保存内容可能丢失的离开操作，不将超时视为保存成功。
- FortuneSheet 1.0.4 只读单元格编辑器的 layout effect 原本无条件提交上下文，分组刷新又改变工作表数组，导致 React maximum update depth 异常。构建时针对该版本增加 `forceFormulaRef` 前置条件，保留只读限制及公式栏；依赖源码改变时补丁明确报错，不能静默失效。
- 报表先保留本地草稿，服务器确认后才显示已保存；仅提交实际用户改变的值/格式，不把公式重算和默认格式归一化当成编辑。切表互斥；租约取得、续租与释放串行；销毁时补充释放迟到锁。不同格可同时保存，同格占用保留草稿供重试。
- 兼容旧 `parentOrigin` 参数仅限报表静态入口且与请求入口同源，其他参数与请求继续接受规则检查。单次规则命中拦截请求，5分钟累计3次才封禁；登录失败阈值10次，并适当增加共用出口请求额度。
- 线上运维新增独立“封禁记录查看与解封”权限；记录规则ID/说明、触发方法/路径、入口、原因和起止时间。旧记录缺失详情如实提示；不保存查询凭据或请求正文，不自动清除既有封禁。
- 用户运行页右上角直接导出 Excel，遵循账号原有导出授权。只读传输不再剥夺这项明确授权；导入模板/添加页面仍需要开发权限。导出前先确认保存，沿用完整原稿格式。
- 用户追加模板文字不得挤压：热/电/水季节表统一增加列宽，按标题文字、字号和合并跨度增加行高并换行，Excel导出同步；这项明确调整原稿几何，原边框/配色/打印设置等继续保留。既有年度表立即使用该显示规则，无需覆盖模板或重建数据。自定义上传页面保持原稿。
- 原生Excel验证发现旧热/水导出件残留已删除辅助页的计算链，Excel要求修复。导出现在仅剔除可重建的calcChain缓存及其包引用，保持全部公式和其他OOXML部件；由Excel按已设置的完整重算标志重建。这项修复同样覆盖已保存的旧原稿，无需重导。

## 使用

覆盖安装完整v78后，浏览器重新加载页面。已导入v77完整原稿的工程无需重复导入模板；旧表缺原稿时仍按v77说明补齐。普通用户在报表右上角“导出 Excel”下载；无按钮时由管理员核对账号导出权限。

以前已封禁的IP需由管理员或获授权账号在“线上运维→封禁与解封”核对并解封；若该客户端本身被封，使用服务器本机或另一未封禁的授权入口。封禁修复不替代白名单及正常登录。

未部署现场、未修改18153或现场数据库。未更新安卓APK。在线复杂公式兼容限制仍沿用v77说明，导出由Excel重算。
