# Go / Flutter 实现约束

唯一母本：[分层契约](../docs/architecture.md)；UI 验收：[桌面体验](../docs/desktop-experience.md)。

## Go

- backend/cmd/server 只装配；transport 只负责认证、格式、调用和响应；application 编排；纯领域规则不导入 Gin、GORM、Paho 或 UI。
- 模块按 projects、points、events、storage、analysis、control 等能力建立；简单 CRUD 可合并服务/数据访问实现，但 handler 不承担流程规则。路径为计划，不预建空层。
- MQTT adapter 规范化值/质量/源时间；回调轻量入队，禁止直接写库。
- 写入统一走 control 用例：身份、目标、范围、编码版本、命令 ID、发送及确认。脚本不能绕过同一入口。
- 规则/存储配置的保存与运行激活显式区分，版本冲突返回可识别错误；导出绑定查询快照。
- 不把原检测会话作为通用存储的业务前置条件。先定位已有独立存储后再确定迁入方式。
- 采集/事件/存储/导出队列必须有界；明确满载策略、缺口及恢复，不能以 QoS 代替应用持久保证。
- 设备写结果未知不自动重放；查询、文件读取等安全操作与物理副作用分别制定重试策略。
- 脚本限制时间/资源，依赖检测循环，质量/陈旧校验，不默认 BAD 为 GOOD。
- 数据库与设备不存在共享事务；多动作保留每步状态，确认部分成功。
- 配置不夹带现场凭据/客户数据；迁入保留来源及许可证。

## Flutter

- app/lib/features 按业务能力组织；shared/api 统一鉴权、错误及 DTO，页面不直接拼请求；平台文件/窗口能力放 platform adapter。
- 前端不连接 MQTT/MySQL/PLC，不自行重算后端工程值或触发业务规则。
- PC-first：键盘、焦点、右键、表格密度、高 DPI、窗口、文件和状态栏是验收项，不能只检查网页截图。
- 共享 token 管理浅色/深色、状态色、密度、字体和间距。大数据表虚拟化，图表降采样不能掩盖原始值。
- Web 共用用例和 DTO，桌面专用 API 必须有平台条件及明确替代；远程认证/重连单独验证。
- 异步任务明确排队/运行/完成/失败/取消；取消 UI 等待不等于撤销设备动作。
- SDK/依赖版本在环境恢复后固定，不能凭空声称 flutter analyze/build 已通过。
