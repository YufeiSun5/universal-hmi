# Embedded process symbols

458 static SVG symbols from the `Proc. Engineering` folder of
[FUXA-SVG-Widgets](https://github.com/frangoteam/FUXA-SVG-Widgets/tree/70e7c4a656d111c0428c77eb4b0409fc3670b8d5),
pinned at `70e7c4a656d111c0428c77eb4b0409fc3670b8d5`.

The upstream MIT license is preserved verbatim in `LICENSE-FUXA.txt` and shown
in the application license screen. MIT permits commercial use with preservation
of its copyright and license notice. The catalog records each original path,
original SHA-256 and modified asset SHA-256.

These are modified static geometry assets: scripts, event handlers, foreign
elements, external references and empty definitions were removed; supported
inline presentation styles were normalized. Embedded scripts are never executed.
Other upstream folders are excluded, including `dynamicSVG` files bearing Opto22
notices. No blanket licensing assertion is made for excluded assets.

To reproduce, extract the archive for that exact revision and run:

```sh
python ci/vendor_process_symbols.py --source /path/to/FUXA-SVG-Widgets-70e7c4a656d111c0428c77eb4b0409fc3670b8d5
python ci/process_symbol_geometry.py
python -m unittest discover -s ci -p test_process_symbols.py
```

These commands run from the repository root. Builds use committed assets without
downloading the source repository. User-added PNG/JPEG images remain the user's
own resources; their rights are separate from this symbol library.

`ci/process_symbol_geometry.py` also reads six original example SVGs and the
ten generated transparent PNGs (their IHDR dimensions), and
generates `app/lib/features/process/symbol_sizes.dart`. Its `--check` mode and the
integrity tests reject stale geometry. Flutter shares one contained viewport and
rotation transform for drawing and pipe anchors. Reviewed example contacts live
in `symbol_geometry.dart`; imported symbols use viewport edges until individual
physical ports are reviewed. Original SVG bytes and upstream provenance remain
unchanged by this connection fix.

The heating monitor additions are project-created resources, separate from the
FUXA MIT subset: `examples/monitor-hx.svg`, `examples/monitor-tank.svg`, and
`examples/heat-exchanger-v1.png`. The PNG was generated with the built-in image
generation tool on 2026-10-26; it is not a vendor photograph or manufacturer
drawing. Its prompt and reviewed pipe contacts are recorded in
`examples/heat-exchanger-v1-provenance.txt`. The monitor template remains an
editable collection of pipes, symbols, text and unbound value elements.

The refined set adds heat-exchanger-v2.png, inline-pump-v1.png, actuated-valve-v1.png, flow-meter-v1.png and pressure-transmitter-v1.png. All were generated with the built-in tool; exact prompts are in examples/equipment-v2-prompts.json. The PNGs retain their original alpha bytes, and contact coordinates were reviewed before integration. No generated object carries a manufacturer logo or simulated running indicator.

The third set adds water-tank-v2.png, electronic-temperature-v1.png,
pressure-sensor-v2.png and relief-valve-v2.png. Exact built-in generation prompts
are in examples/equipment-v3-prompts.json. The sectional tank uses brushed steel
panels; the two instruments have distinct silhouettes; the angle safety valve
uses a bottom inlet and side discharge. These are visual reference assets, not
manufacturer-certified mechanical drawings. The template is reproducible with
`python ci/build_heating_monitor_template.py` from the repository root.

Four anonymous heating variants are generated by `python ci/build_heating_variants.py`.
Use `python ci/build_heating_variants.py --check` to verify committed outputs.
They contain editable elements, static arrows and unbound measurement placeholders;
loading a template assigns the chosen scope through the existing instantiate flow.
